01Microcontrollers & the embedded mindset

What you will learn

  • Explain what a microcontroller contains
  • Reason about memory, timing, power, and hardware constraints
  • Explain how microcontroller changes the behavior, result, or engineering decision in a concrete example
  • Connect microcontroller with flash and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

A microcontroller combines a CPU, flash, RAM, timers, communication peripherals, and GPIO on one device, usually under tighter memory, power, timing, and cost constraints than a desktop computer. Firmware often interacts directly with hardware registers or device drivers and may need predictable timing.

Key concepts

microcontrollerflashRAMperipheralsconstraints

Example

state = {"led": False, "temperature": 22.4}
print("boot", state)
Common mistake: Designing as if the device has desktop-class memory, power, storage, and timing.
02GPIO: digital inputs & outputs

What you will learn

  • Model digital pin states safely
  • Explain pull-up logic
  • Debounce an input without blocking

Explanation

GPIO pins can be configured as digital inputs or outputs. Inputs can float unless pull-up or pull-down resistors establish a known default level.

Key concepts

GPIOpull-updebouncingedge detection

Example

samples = [1, 1, 0, 0, 0, 1]
stable = samples[-3:]
pressed = stable == [0, 0, 0]
print("pressed:", pressed)
Common mistake: Reading a button or digital input without a defined pull-up/pull-down or debounce strategy, causing floating or repeated transitions to look like real events.
03Timers, delays & interrupts

What you will learn

  • Replace long blocking delays
  • Model timer-driven work
  • Keep event handlers short

Explanation

Timers provide hardware-based time measurement so firmware does not have to waste CPU cycles in long busy-wait loops. Interrupts let hardware signal that an event needs attention, but interrupt handlers should remain short because they can delay other time-sensitive work.

Key concepts

timerinterruptevent looplatencynon-blocking

Example

import asyncio

async def sample_sensor():
    for tick in range(3):
        print("sample", tick)
        await asyncio.sleep(0)

asyncio.run(sample_sensor())
Common mistake: Using long blocking delays inside the main control loop, which prevents the device from responding to other events on time.
04ADC, PWM & analog signals

What you will learn

  • Interpret ADC resolution
  • Map sensor input to output
  • Explain PWM duty cycle

Explanation

An ADC converts an analog voltage into a discrete digital number. Resolution determines how many distinct codes are available, while sampling rate determines how often the signal is measured.

Key concepts

ADCsamplingresolutionPWMduty cycle

Example

raw = 2530
max_adc = 4095
volts = raw * (3.3 / max_adc)
duty = round(raw / max_adc * 100, 1)
print(volts, duty)
Common mistake: Treating ADC readings and PWM output as perfectly exact analog values.
05UART, I²C & SPI communication

What you will learn

  • Choose an appropriate bus
  • Explain addressing and clocking
  • Design a small device communication layer

Explanation

UART, I²C, and SPI solve different communication needs. UART is asynchronous point-to-point serial communication.

Key concepts

UARTI2CSPIbusaddressing

Example

class DeviceBus:
    def read(self, address):
        return {"address": address, "value": 42}

bus = DeviceBus()
print(bus.read(0x3C))
Common mistake: Mixing UART/I2C/SPI details directly into application logic.
06Sensors, actuators & device drivers

What you will learn

  • Build a driver boundary
  • Calibrate raw sensor values
  • Protect outputs with safe limits

Explanation

A device driver translates application-level intent into the register operations or bus messages a specific sensor or actuator expects. Sensors often require calibration, scaling, unit conversion, and plausibility checks before raw readings become useful data.

Key concepts

drivercalibrationsensoractuatorfault handling

Example

class TemperatureSensor:
    def read_celsius(self, raw):
        if not 0 <= raw <= 4095:
            raise ValueError("invalid sample")
        return raw * 100 / 4095

print(round(TemperatureSensor().read_celsius(2050), 2))
Common mistake: Using raw sensor values as trustworthy application data without calibration, unit conversion, range checks, timeout handling, or a defined safe response to device failure.
07Firmware architecture & state machines

What you will learn

  • Model device modes explicitly
  • Design deterministic transitions
  • Add a safe fault state

Explanation

A state machine makes firmware behavior explicit by listing valid states, the events that cause transitions, and the actions performed on entry or transition. This is often safer than a collection of loosely related flags.

Key concepts

state machineevent loopdeterminismwatchdogfault state

Example

from enum import Enum
class State(Enum):
    IDLE = "idle"
    RUNNING = "running"
    FAULT = "fault"

state = State.IDLE
temperature = 82
state = State.FAULT if temperature > 70 else State.RUNNING
print(state.value)
Common mistake: Representing modes with scattered booleans and implicit rules instead of explicit states and transitions, making impossible states and unsafe transitions hard to detect.
08Embedded testing & debugging

What you will learn

  • Unit-test hardware-independent logic
  • Use logs effectively
  • Plan simulation and hardware tests

Explanation

Embedded testing combines ordinary unit tests with hardware-aware techniques. Logic can often be tested on a host computer or simulator, while integration tests exercise real peripherals.

Key concepts

unit testingloggingsimulationassertionfault injection

Example

def should_start(temp, interlock):
    return interlock and temp < 70

assert should_start(30, True)
assert not should_start(80, True)
print("logic tests passed")
Common mistake: Testing only on physical hardware or only on the happy path.
