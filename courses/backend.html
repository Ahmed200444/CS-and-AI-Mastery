Explanation

Key concepts

HTTP methodsstatus codesrequest/response404

Example

GET /users/5   -> 200 + JSON
POST /users    -> 201 Created
Common mistake: Using GET for an operation that changes server state -- GET requests can be cached, prefetched, or retried automatically.
02Servers: what happens when a request arrives

What you will learn

  • Trace a request from the network to your application code
  • Apply the KHDA-benchmarked professional additions in a realistic company workflow: middleware, environment-based configuration, structured logging.
  • Explain how server process changes the behavior, result, or engineering decision in a concrete example
  • Connect server process with port and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

A server is a process listening on a port for incoming connections. When a request arrives, the OS hands it to your server process, which parses the HTTP request, routes it to the right handler function based on method+path, runs your code, and sends a response back down the same connection.

Professional benchmark addition: These company-use concepts were kept after comparing the course with public syllabi from KHDA-listed Dubai training providers: middleware, environment-based configuration, structured logging.

Key concepts

server processportrequest routingsocket (concept)middlewareenvironment-based configurationstructured logging

Example

# conceptually, before any framework:
# 1. socket accepts a connection
# 2. read raw bytes, parse method+path+headers
# 3. match against your routes
# 4. call the matching function, get a response
# 5. write the response bytes back, close/keep-alive the connection
Common mistake: Assuming 'the server' is one mysterious black box — it's normal application code, listening on a port, that you could largely write yourself.
03Databases & persistence for backend services

What you will learn

  • Explain why backend services need persistent storage
  • Connect a basic ORM/query layer conceptually
  • Explain how persistence changes the behavior, result, or engineering decision in a concrete example
  • Connect persistence with ORM and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

Persistence means keeping application state beyond the lifetime of one process. In a backend service, an ORM can map application objects to database rows, but the database schema is still a production contract that changes over time.

Key concepts

persistenceORMin-memory vs durable storagedatabase migrationbackward-compatible schema changemigration rollback

Example

# raw SQL
cursor.execute("SELECT * FROM users WHERE id = %s", (user_id,))

# ORM equivalent (conceptually)
user = User.objects.get(id=user_id)
Common mistake: Storing real user data only in memory 'to move fast' — a restart, deploy, or crash means total data loss.

05Authentication: sessions vs tokens

What you will learn

  • Contrast session-based and token-based (JWT) authentication
  • Explain how session changes the behavior, result, or engineering decision in a concrete example
  • Connect session with JWT and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

Authentication proves who's making a request. Session-based auth stores a session ID in a cookie, which the server looks up against server-side state on every request.

Key concepts

sessionJWTstateless authtoken expiry

Example

# session: cookie holds session_id -> server looks up user in a session store
# JWT: cookie/header holds a signed token -> server verifies signature, no lookup
# JWT payload (decoded): {"user_id": 42, "exp": 1234567890}
Common mistake: Storing sensitive data unencrypted inside a JWT payload — JWTs are signed (tamper-proof) but NOT encrypted by default; anyone can decode and read the payload.
06Building an API with FastAPI

What you will learn

  • Define a path operation with FastAPI that validates input automatically
  • Explain how FastAPI changes the behavior, result, or engineering decision in a concrete example
  • Connect FastAPI with path operations and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

FastAPI turns Python functions into HTTP endpoints with automatic validation and docs. A path operation maps a URL+method to a function.

Key concepts

FastAPIpath operationstype validationauto docs

Example

from fastapi import FastAPI
app = FastAPI()

@app.get('/hello/{name}')
def hello(name: str):
    return {'msg': f'Hi {name}'}
Common mistake: Skipping type hints on path operation parameters -- FastAPI's automatic validation and docs generation depend on them.
07Security & input validation

What you will learn

  • Identify and prevent the most common backend vulnerabilities

  • Explain how SQL injection changes the behavior, result, or engineering decision in a concrete example
  • Connect SQL injection with input validation and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

Never trust client input. SQL injection happens when user input is concatenated directly into a query instead of using parameterized queries.

Professional benchmark addition: These company-use concepts were kept after comparing the course with public syllabi from KHDA-listed Dubai training providers: CORS, password hashing, safe file upload/download.

Key concepts

SQL injectioninput validationparameterized queriesrate limitingCORSpassword hashingsafe file upload/download

Example

# VULNERABLE:
query = f"SELECT * FROM users WHERE name = '{user_input}'"

# SAFE: parameterized query, the driver handles escaping
cursor.execute("SELECT * FROM users WHERE name = %s", (user_input,))
Common mistake: Building your own string-concatenation 'escaping' instead of using parameterized queries/prepared statements — this is how real SQL injection breaches happen, repeatedly, in production.
08Scaling & backend architecture

What you will learn

  • Identify the first few scaling levers for a growing backend service
  • Explain how caching changes the behavior, result, or engineering decision in a concrete example
  • Connect caching with load balancing and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

Backend scaling is not only adding more servers. Caches reduce repeated work, load balancers distribute requests, read replicas can move read traffic away from the primary database, and background-job queues move slow work out of the request path.

Key concepts

cachingload balancingbackground jobsread replicasidempotencyretry with exponential backoffdead-letter queue

Example

# request path once it starts scaling:
users -> load balancer -> [server, server, server] -> cache -> database (+ read replicas)
#                                                    -> background queue (emails, etc.)
Common mistake: Prematurely over-engineering for scale you don't have yet — profile and scale the ACTUAL bottleneck, not a guessed one.
09Async FastAPI, concurrency & request safety

What you will learn

  • Use async endpoints appropriately and identify when shared mutable state needs synchronization
  • Explain how async def changes the behavior, result, or engineering decision in a concrete example
  • Connect async def with await and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

Async web frameworks let one process keep serving other requests while a request waits on non-blocking I/O. Use async def when the libraries you call are async and you have many I/O waits; CPU-heavy work should not block the event loop.

Key concepts

async defawaitFastAPII/O-boundconnection pool

Example

from fastapi import FastAPI
import asyncio

app = FastAPI()

@app.get("/health")
async def health():
    await asyncio.sleep(0)
    return {"ok": True}
Common mistake: Adding async to a function that still calls long blocking libraries.
