02Files & directories: ls, cd, pwd, mkdir, cp, mv, rm

What you will learn

  • Navigate and manage files and directories from the command line
  • Explain how ls changes the behavior, result, or engineering decision in a concrete example
  • Connect ls with cd and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

Linux files and directories form a hierarchical filesystem. `pwd` shows your current directory, `ls` lists its contents, and commands such as `cd`, `mkdir`, `cp`, `mv`, and `rm` let you navigate and manage files. The key is understanding relative and absolute paths so you know exactly which location a command will affect.

Key concepts

lscdpwdmkdircpmvrmrm -r

Example

pwd                    # /home/user
ls
cd ..
mkdir new_folder
cp source.txt dest.txt
mv old_name.txt new_name.txt
rm -r old_folder
Common mistake: Running rm -r on the wrong directory -- there's no recycle bin by default, so double-check the path before pressing enter.
03Absolute vs relative paths, and `~`

What you will learn

  • Distinguish absolute from relative paths
  • Explain how absolute path changes the behavior, result, or engineering decision in a concrete example
  • Connect absolute path with relative path and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

An absolute path starts from the root directory / and fully specifies a location regardless of where you currently are. A relative path is interpreted relative to your current working directory.

Key concepts

absolute pathrelative path~

Example

cd /home/user/projects   # absolute -- works from anywhere
cd projects                # relative -- only works if you're already in /home/user
cd ~                       # jumps to your home directory
Common mistake: Using a relative path in a script that might run from a different working directory -- it silently looks in the wrong place.

Explanation

cat prints a file's entire contents. head shows the first lines (head -n 5 for the first 5); tail shows the last, and tail -f keeps watching for new lines appended in real time -- useful for live log files.

Key concepts

catheadtailtail -fgrepfind

Example

Common mistake: Using cat on a huge file when you only need the first or last few lines -- head/tail are faster and don't flood your terminal.
05Redirection & pipes in depth

What you will learn

  • Redirect output to files and chain commands together with pipes
  • Explain how redirect > changes the behavior, result, or engineering decision in a concrete example
  • Connect redirect > with >> and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

> writes a command's output to a file, overwriting anything already there. >> appends instead of overwriting.

Key concepts

redirect >>>pipe |

Example

echo "hello" > out.txt       # overwrites out.txt
echo "again" >> out.txt      # appends to out.txt
cat log.txt | grep "error"   # pipes cat's output into grep
Common mistake: Using > when you meant >> -- this silently overwrites and destroys the file's previous contents.

  • Explain how environment variable changes the behavior, result, or engineering decision in a concrete example
  • Connect environment variable with export and predict what changes when one assumption changes

Explanation

An environment variable (set with `export NAME=value`) is available to any program launched from that shell -- PATH is the most important one: a list of directories the shell searches, in order, when you type a command name, which is why 'command not found' often means the program either isn't installed or isn't in a directory PATH includes.

Key concepts

12Networking & Remote Access: curl, SSH & scp

What you will learn

  • Connect to a remote server over SSH and use curl/scp to interact with it
  • Explain how SSH changes the behavior, result, or engineering decision in a concrete example
  • Connect SSH with ssh key and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

SSH (Secure Shell) lets you log into and run commands on a remote machine over an encrypted connection -- `ssh user@host` opens a remote shell session, and SSH keys (a public/private key pair) let you authenticate without typing a password every time, which is both more convenient and more secure than password auth.

Key concepts

SSHssh keypublic/private key pairscpcurlremote serverencrypted connection

Example

ssh ahmed@my-server.example.com          # open a remote shell session
scp local-file.txt ahmed@my-server:/home/ahmed/   # copy a file TO the server
scp ahmed@my-server:/var/log/app.log .            # copy a file FROM the server

curl https://api.example.com/health      # quick check: is this endpoint responding?
curl -X POST -d '{"key":"value"}' https://api.example.com/data
Common mistake: Relying on password authentication for SSH instead of setting up key-based auth -- beyond being less convenient, password auth over SSH is a much more common target for automated brute-force.
