01The forward noising process

What you will learn

  • Explain how the forward diffusion process gradually destroys an image
  • Explain how forward process changes the behavior, result, or engineering decision in a concrete example
  • Connect forward process with progressive noising and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

The forward process takes a real image and gradually adds a small amount of random (Gaussian) noise over many steps, until after enough steps the image is indistinguishable from pure noise. This process is fixed and mathematically defined (not learned) — the actual learning happens in the REVERSE direction, covered next.

Key concepts

forward processprogressive noisingfixed (non-learned) processforward noising process

Example

x_0 = real_image
for t in range(1, num_steps):
    x_t = sqrt(1 - beta_t) * x_(t-1) + sqrt(beta_t) * noise
# after enough steps, x_T looks like pure random noise, regardless of the original image
Common mistake: Assuming the forward process is learned or trainable — it's a fixed mathematical recipe; the model only learns to REVERSE it, which is the actual generative task.
02The reverse denoising process

What you will learn

  • Explain what the model actually learns in diffusion training
  • Explain how reverse process changes the behavior, result, or engineering decision in a concrete example
  • Connect reverse process with learned denoising and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

The model is trained to do the OPPOSITE of the forward process: given a noisy image at some step, predict and remove a bit of that noise, recovering a slightly less noisy version.

Key concepts

reverse processlearned denoisingiterative refinement

Example

x_T = pure_random_noise
for t in reversed(range(1, num_steps)):
    predicted_noise = model(x_t, t)
    x_(t-1) = denoise_one_step(x_t, predicted_noise, t)
# after all steps: x_0 is a generated, coherent image
Common mistake: Expecting the model to produce a good image in one single step — diffusion's whole approach relies on many small, easier denoising steps rather than one hard leap from noise to image.

06Conditioning & latent diffusion

What you will learn

  • Explain how diffusion models are conditioned on text, and why latent diffusion is more efficient
  • Explain how cross-attention conditioning changes the behavior, result, or engineering decision in a concrete example
  • Connect cross-attention conditioning with latent diffusion and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

Text-to-image conditioning typically feeds a text encoder's embedding (often from a transformer, connecting directly to the Transformers track) into the U-Net at each denoising step via cross-attention, the same attention mechanism from the Transformers track, letting image regions attend to relevant words.

Key concepts

cross-attention conditioninglatent diffusioncompute efficiency

Example

# latent diffusion:
compressed = vae_encoder(image)     # much smaller than raw pixels
# run the whole forward/reverse diffusion process on 'compressed', not the raw image
final_image = vae_decoder(denoised_compressed)   # decode back to full resolution at the very end
Common mistake: Assuming diffusion models always operate on raw pixel space — most modern production systems (this is precisely what 'latent diffusion' means) work in a compressed latent space for efficiency, only decoding to pixels at the final step.
