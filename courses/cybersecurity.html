01The attacker's mindset & threat modeling

What you will learn

  • Think through a system from an attacker's perspective, not just a builder's
  • Explain how attacker's mindset changes the behavior, result, or engineering decision in a concrete example
  • Connect attacker's mindset with threat modeling and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

Secure systems aren't built by asking 'does this work' alone — they're built by also asking 'how could someone abuse this.' Threat modeling systematically walks through a system's entry points (login forms, file uploads, APIs) and asks what a malicious actor could do at each one, BEFORE it ships, rather than discovering it after a breach.

Key concepts

attacker's mindsetthreat modelingentry points

Example

# threat modeling a login form:
# - what if someone submits 10,000 password guesses per second? (needs rate limiting)
# - what if someone submits a SQL query as the username? (needs input validation)
# - what if someone intercepts the request over an unencrypted connection? (needs HTTPS)
Common mistake: Only testing that a feature works for legitimate, well-behaved input — security bugs live specifically in the malicious, unexpected, or malformed inputs a normal test plan never tries.

04The CIA triad: confidentiality, integrity, availability

What you will learn

  • Explain the three core security properties the CIA triad names
  • Explain how CIA triad changes the behavior, result, or engineering decision in a concrete example
  • Connect CIA triad with confidentiality and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

The CIA triad names the three properties security work protects: Confidentiality (only authorized parties can view data), Integrity (data isn't modified without authorization, accidentally or maliciously), and Availability (systems and data remain accessible to legitimate users when needed).

Key concepts

CIA triadconfidentialityintegrityavailability

Example

# a stolen customer database = confidentiality breach
# a tampered financial record = integrity breach
# a DDoS attack taking a site offline = availability breach
# same triad, three very different kinds of harm
Common mistake: Treating security as only about 'keeping data secret' (confidentiality) while overlooking integrity and availability, which are equally real security properties.

Knowledge checks

Threat modeling is best done:
  1. after a breach occurs
  2. before a feature ships, during design
  3. only for financial applications
  4. never, it's not worth the time
Cross-site scripting (XSS) typically results from:
  1. a weak password policy
  2. rendering untrusted input as HTML/JavaScript without escaping
  3. using HTTPS
  4. having too many API endpoints
Authorization answers the question:
  1. who are you?
  2. what are you allowed to do?
  3. how strong is your password?
  4. which server are you on?
Passwords should generally be stored:
  1. encrypted, so they can be decrypted later
  2. hashed with a purpose-built password-hashing algorithm
  3. in plain text for easy recovery
  4. in a spreadsheet
HTTPS/TLS primarily protects data:
  1. stored on disk
  2. in transit between client and server
  3. inside a compiled binary
  4. in source control
What does the CIA triad stand for in security?
  1. Confidentiality, Integrity, Availability
  2. Control, Inspection, Access
  3. Cryptography, Identity, Authorization
  4. Certification, Isolation, Auditing
What does 'confidentiality' in the CIA triad protect against?
  1. data being deleted
  2. unauthorized parties viewing sensitive data
  3. the system going offline
  4. slow performance
What does 'integrity' in the CIA triad protect against?
  1. unauthorized viewing of data
  2. unauthorized or accidental modification of data
  3. the system going offline
  4. password reuse
What does 'availability' in the CIA triad ensure?
  1. data is encrypted
  2. systems and data remain accessible to authorized users when needed
  3. only authorized users can view data
  4. passwords are hashed
What is the difference between authentication and authorization?
  1. they're identical
  2. authentication verifies WHO you are; authorization determines WHAT you're allowed to do
  3. authorization happens before authentication always
  4. authentication only applies to passwords
Why hash passwords instead of encrypting them?
  1. hashing and encryption are identical for this purpose
  2. hashing is one-way, so even if the hash is stolen, the original password can't be directly recovered from it
  3. encryption is always weaker than hashing
  4. passwords should never be transformed at all
What does 'one-way' mean for a hash function?
  1. it can be reversed with the right key
  2. you can't feasibly reconstruct the original input from the hash output
  3. it only works one time per password
  4. it means the hash is always the same length as the input
Why is a slow, purpose-built hashing algorithm (like bcrypt) preferred for passwords over a fast general-purpose hash?
  1. speed doesn't matter for password hashing
  2. slowness deliberately makes brute-force password-guessing attacks much more expensive for an attacker
  3. fast hashes are always more secure
  4. bcrypt is faster, which is why it's preferred
What is the difference between hashing and encryption?
  1. they're the same technique
  2. hashing is one-way and irreversible; encryption is two-way and can be decrypted with the right key
  3. encryption is always one-way
  4. hashing requires a decryption key
What is SQL injection?
  1. a database performance issue
  2. an attack where untrusted input is inserted into a SQL query in a way that changes its intended logic
  3. a type of encryption
  4. a synonym for XSS
What is the standard defense against SQL injection?
  1. escaping quotes manually only
  2. parameterized queries/prepared statements, which separate query structure from user data
  3. disabling the database
  4. using a faster database
What is cross-site scripting (XSS)?
  1. a network configuration issue
  2. injecting malicious script into a web page that then runs in other users' browsers
  3. a synonym for SQL injection
  4. a type of password attack
What is the standard defense against XSS?
  1. hashing all input
  2. properly escaping/encoding user-controlled content before rendering it in HTML
  3. disabling JavaScript entirely
  4. using a faster server
What does CSRF stand for?
  1. Cross-Site Resource Fetching
  2. Cross-Site Request Forgery
  3. Certified Secure Request Framework
  4. Cryptographic Session Reset Function
How does a CSRF attack work?
  1. it injects a malicious script into a page
  2. it tricks a logged-in user's browser into submitting an unwanted request to a site they're authenticated on
  3. it steals passwords directly from a database
  4. it floods a server with traffic
What is a standard defense against CSRF?
  1. hashing passwords
  2. using CSRF tokens that a malicious third-party site can't know or forge
  3. disabling cookies entirely
  4. encrypting all network traffic
What does the principle of least privilege mean?
  1. giving every user maximum access for convenience
  2. granting only the minimum access/permissions actually needed to perform a task
  3. only applying to system administrators
  4. disabling all permissions by default with no exceptions
Why does least privilege reduce security risk?
  1. it doesn't reduce risk meaningfully
  2. limiting access limits the potential damage if an account or system is compromised
  3. least privilege only matters for physical security
  4. broader access is always more secure
What does the OWASP Top 10 represent?
  1. a list of programming languages
  2. a widely-referenced, regularly-updated list of the most critical web application security risks
  3. a certification exam
  4. a type of firewall
What does TLS/HTTPS primarily provide?
  1. faster page load times
  2. encrypted communication between a client and server, protecting data in transit
  3. password hashing
  4. protection against SQL injection specifically
What is broken access control?
  1. a hardware failure
  2. a flaw where users can access resources or perform actions they shouldn't be authorized for
  3. a type of encryption weakness only
  4. a synonym for CSRF specifically
Why check permissions on every request, not just at login?
  1. checking once at login is always sufficient
  2. a user's permissions or session validity can change, and per-request checks prevent using a stale or escalated authorization
  3. per-request checks always slow down the system unacceptably
  4. this only matters for banking applications
What does 'shift-left security' mean?
  1. moving security responsibilities to a separate team entirely
  2. addressing security considerations earlier in the development process, rather than only at the end
  3. a synonym for penetration testing
  4. disabling security checks during development
What is the purpose of dependency scanning?
  1. speeding up builds
  2. identifying known vulnerabilities in third-party libraries/packages a project depends on
  3. formatting code automatically
  4. a synonym for penetration testing
What is penetration testing?
  1. a type of load testing
  2. authorized, simulated attacks against a system to find real exploitable vulnerabilities before attackers do
  3. a synonym for dependency scanning
  4. a code style checker
