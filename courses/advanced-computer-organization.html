01Pipeline fundamentals & CPI

What you will learn

  • Explain instruction pipelining
  • Calculate CPI
  • Separate throughput from latency

Explanation

A pipeline splits instruction execution into stages so different instructions can occupy different stages at the same time. Throughput can improve even though the latency of one instruction does not necessarily shrink.

Key concepts

pipelineCPIthroughputlatencystall

Example

instructions = 1200
cycles = 1560
cpi = cycles / instructions
print(f"CPI={cpi:.2f}")
Common mistake: Confusing instruction latency with throughput or assuming a deeper pipeline always makes a single instruction finish faster.
02Data, control & structural hazards

What you will learn

  • Classify pipeline hazards
  • Explain forwarding
  • Estimate stall impact

Explanation

Pipeline hazards are reasons the next instruction cannot advance safely. A RAW data hazard occurs when an instruction needs a result that an earlier instruction has not produced yet; forwarding can bypass that result directly to a later stage.

Key concepts

RAW hazardforwardingcontrol hazardstructural hazardbubble

Example

ops = [("LOAD", "R1"), ("ADD", "R1"), ("STORE", "R2")]
stalls = sum(1 for i in range(1, len(ops)) if ops[i-1][1] == ops[i][1])
print("estimated stalls:", stalls)
Common mistake: Assuming forwarding removes every pipeline hazard.
03Branch prediction & speculation

What you will learn

  • Explain branch prediction
  • Measure misprediction cost
  • Compare predictors

Explanation

Branch prediction guesses the control-flow direction before the branch is fully resolved so the pipeline can keep fetching useful work. A branch target buffer can remember likely target addresses, while direction predictors learn whether a branch tends to be taken.

Key concepts

branch predictorspeculationmispredictionBTBpipeline flush

Example

predicted = [True, True, False, True]
actual = [True, False, False, True]
correct = sum(p == a for p, a in zip(predicted, actual))
print("accuracy:", correct / len(actual))
Common mistake: Looking only at branch-predictor accuracy.
04Cache hierarchy & locality

What you will learn

  • Explain temporal/spatial locality
  • Calculate average memory access time
  • Predict cache-friendly code

Explanation

Caches exploit temporal locality, where recently used data is likely to be reused, and spatial locality, where nearby data is likely to be accessed soon. A cache hit is served from a faster level; a miss requires a slower level.

Key concepts

cachelocalityhitmissAMAT

Example

hit_time = 1
miss_rate = 0.08
miss_penalty = 80
amat = hit_time + miss_rate * miss_penalty
print("AMAT:", amat)
Common mistake: Reasoning about cache size without the workload access pattern.
05Associativity, replacement & write policies

What you will learn

  • Compare cache organizations
  • Explain replacement
  • Compare write policies

Explanation

Associativity controls how many cache locations can hold a particular memory block, replacement policy decides which resident block is evicted, and write policy decides when modified data reaches the next memory level. Direct-mapped caches are simple but can suffer conflict misses; set-associative designs reduce those conflicts at extra hardware cost.

Key concepts

associativityLRUwrite-backwrite-throughconflict miss

Example

addresses = [0, 4, 8, 16, 0, 4]
line_size = 4
sets = 4
for address in addresses:
    block = address // line_size
    print(address, "set", block % sets)
Common mistake: Treating associativity, replacement policy, and write policy as the same design choice.
06Virtual memory & TLB behavior

What you will learn

  • Explain address translation
  • Describe TLB hits/misses
  • Connect page size to trade-offs

Explanation

Virtual memory gives each process its own address space and maps virtual pages to physical frames through page tables. A TLB is a small cache of recent address translations.

Key concepts

virtual memoryTLBpage tablepage faulttranslation

Example

address = 0x12345
page_size = 4096
page, offset = divmod(address, page_size)
print("page", page, "offset", offset)
Common mistake: Treating a TLB miss as a page fault.
07Multicore caches & coherence

What you will learn

  • Explain why private caches disagree
  • Describe invalidation coherence
  • Recognize false sharing

Explanation

Private per-core caches improve speed but create a consistency problem when multiple cores access data that maps to copies in different caches. Coherence protocols coordinate ownership and invalidation so writes become visible correctly.

Key concepts

cache coherenceinvalidationfalse sharingmulticorecontention

Example

workers = {"core0": [0, 64], "core1": [4, 68]}
line_size = 64
for core, addresses in workers.items():
    print(core, [address // line_size for address in addresses])
Common mistake: Confusing false sharing with a data race.
08Performance measurement & roofline thinking

What you will learn

  • Separate compute-bound from memory-bound behavior
  • Use measurements and models
  • Explain a measured bottleneck

Explanation

Performance engineering begins with a reproducible workload and measurement. Hardware counters can reveal cache misses, branch misses, cycles, instructions, and other evidence.

Key concepts

benchmarkinghardware countermemory bandwidthcompute boundroofline

Example

import time
start = time.perf_counter()
value = sum(i * i for i in range(50000))
elapsed = time.perf_counter() - start
print(value, round(elapsed, 6))
Common mistake: Trusting one noisy timing run or a benchmark that does not represent the real workload.
