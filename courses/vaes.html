01Autoencoders & latent spaces

What you will learn

  • Explain what a plain autoencoder learns and why VAEs extend it
  • Explain how autoencoder changes the behavior, result, or engineering decision in a concrete example
  • Connect autoencoder with encoder/decoder and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

A plain autoencoder learns to compress input data into a smaller latent representation (the encoder), then reconstruct the original from it (the decoder) — trained purely to minimize reconstruction error. This forces the latent space to capture the data's essential structure.

Key concepts

autoencoderencoder/decoderlatent spacecompression

Example

encoded = encoder(input_image)      # compress to a small latent vector
reconstructed = decoder(encoded)     # try to rebuild the original from it
loss = reconstruction_error(input_image, reconstructed)
Common mistake: Assuming a plain (non-variational) autoencoder can generate new realistic samples just by feeding random noise into its decoder — its latent space usually has gaps and irregular structure.
02Probabilistic encoders: mean & variance outputs

What you will learn

  • Explain what a VAE's encoder outputs instead of a single point
  • Explain how mean output changes the behavior, result, or engineering decision in a concrete example
  • Connect mean output with variance output and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

Instead of encoding an input to one fixed latent vector, a VAE's encoder outputs the PARAMETERS of a probability distribution for that input — typically a mean vector and a variance (or log-variance) vector describing a Gaussian.

Key concepts

mean outputvariance outputGaussian latent distributionencoder outputsprobabilisticdeterministic

Example

mean, log_variance = encoder(input_image)
# instead of ONE latent vector, we now have a distribution:
# a Gaussian centered at 'mean' with spread controlled by 'log_variance'
Common mistake: Treating the mean output alone as 'the' latent code and ignoring the variance — the variance is doing real work, controlling how much the model believes this exact region of latent space should be treated as similar/interchangeable.
03The reparameterization trick

What you will learn

  • Explain why VAEs need the reparameterization trick to train with backpropagation
  • Explain how reparameterization trick changes the behavior, result, or engineering decision in a concrete example
  • Connect reparameterization trick with non-differentiable sampling and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

You can't backpropagate through a random sampling step directly — 'sample randomly' has no gradient. The reparameterization trick sidesteps this: instead of sampling directly from the distribution, you sample a fixed random noise value from a standard normal, then transform it using the mean and variance (z = mean + noise * std_dev).

Key concepts

reparameterization tricknon-differentiable samplinggradient flow

Example

noise = sample_standard_normal()          # random, but NOT something we backprop through
z = mean + noise * exp(0.5 * log_variance)  # now this IS differentiable w.r.t. mean/log_variance
reconstructed = decoder(z)
Common mistake: Trying to backpropagate directly through a sampling operation without this trick — training simply won't work, since 'randomly sample from a distribution' has no defined gradient with respect to the distribution's parameters.
04Reconstruction loss & KL divergence

What you will learn

  • Explain the two competing terms in a VAE's loss function
  • Explain how reconstruction loss changes the behavior, result, or engineering decision in a concrete example
  • Connect reconstruction loss with KL divergence and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

A VAE's loss balances two goals: reconstruction loss (the decoded output should look like the original input — same as a plain autoencoder) and KL divergence (the learned latent distribution for each input should stay close to a simple reference, usually a standard normal distribution).

Key concepts

reconstruction lossKL divergencethe two-term VAE loss

Example

loss = reconstruction_loss(input, output) + kl_divergence(learned_distribution, standard_normal)
# reconstruction: 'does the output look like the input?'
# KL term: 'is the latent space staying smooth/regularized, not cheating into tiny isolated spikes?'
Common mistake: Weighting the KL term too heavily — the model prioritizes a perfectly smooth latent space at the cost of blurry, low-quality reconstructions; this trade-off (sometimes tuned via a beta-VAE.
05The evidence lower bound (ELBO)

What you will learn

  • Explain what the ELBO is and why VAEs optimize it instead of the true likelihood directly
  • Explain how evidence lower bound changes the behavior, result, or engineering decision in a concrete example
  • Connect evidence lower bound with intractable likelihood and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

Directly computing how likely the training data is under the model (the 'evidence') is mathematically intractable for VAEs. Instead, VAEs optimize the ELBO (Evidence Lower BOund) — a computable quantity that's guaranteed to be a lower bound on the true (intractable) likelihood.

Key concepts

evidence lower boundintractable likelihoodvariational inferencetrue data likelihoodintractable

Example

# ELBO = reconstruction term - KL term (same two pieces from the previous lesson!)
# maximizing ELBO is mathematically equivalent to minimizing the loss shown earlier
# it's the theoretical justification FOR that specific loss formula
Common mistake: Treating the ELBO as a separate, extra concept from the reconstruction+KL loss already covered — they're the same thing viewed from two angles: one is the practical loss formula, the other is its theoretical justification.

07Sampling from latent space & conditional VAEs

What you will learn

  • Generate new samples from a trained VAE and explain conditional VAEs
  • Explain how latent sampling changes the behavior, result, or engineering decision in a concrete example
  • Connect latent sampling with conditional VAE and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

To generate a genuinely new sample, you don't need an input image at all — just sample a random point directly from the reference distribution (standard normal) and run it through the decoder alone; the smooth, regularized latent space (thanks to the KL term) makes this produce coherent outputs, unlike a plain autoencoder.

Key concepts

latent samplingconditional VAEunconditional generationgenerate a brand-new sample

Example

z = sample_standard_normal(latent_dim)   # no input image needed at all
generated = decoder(z)                    # a genuinely NEW sample

# conditional VAE: decoder(z, label='smiling') -- steer what gets generated
Common mistake: Forgetting that a VAE's real generative power comes from sampling from the PRIOR (standard normal) directly, not from re-encoding existing inputs — re-encoding is just reconstruction, not true generation.

Explanation

A well-trained VAE's latent space often captures meaningful, DISENTANGLED structure — moving along one latent dimension might smoothly change an image's rotation, another its brightness, largely independently.

Key concepts

disentangled representationslatent interpolationdownstream use of latent space

Example

# smooth interpolation in latent space:
# z_between = 0.5 * z_cat + 0.5 * z_dog
# decoder(z_between) often produces something visually 'between' cat and dog
# -- only works well because the latent space is smooth and continuous
Common mistake: Assuming disentanglement is automatic — vanilla VAEs get SOME of this for free from the smooth latent space, but genuinely well-disentangled representations often need additional techniques.
09Comparison with GANs

What you will learn

  • Contrast VAEs and GANs on training stability, output quality, and latent space structure
  • Explain how training stability trade-off changes the behavior, result, or engineering decision in a concrete example
  • Connect training stability trade-off with output sharpness trade-off and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

VAEs train more stably (a single well-defined loss to minimize, no adversarial dynamics) and give a smooth, structured, interpretable latent space — but their outputs are often blurrier than GANs', a known VAE weakness from the reconstruction-loss formulation.

Key concepts

training stability trade-offoutput sharpness trade-offstructured latent space

Example

# rough rule of thumb:
# need stable training + interpretable latent space + some blur is OK -> VAE
# need the sharpest possible outputs + can tolerate trickier training -> GAN
# need the best of both worlds for high-quality generation -> often diffusion models today
Common mistake: Picking a model family based on hype rather than these concrete, well-documented trade-offs — this comparison is exactly the kind of grounded reasoning expected in a real architecture-choice.

Explanation

Quantization reduces a model's numerical precision (e.g. from 32-bit to 8-bit) to shrink its size and speed up inference, at a small, often acceptable cost in accuracy.

Key concepts

quantizationinference optimizationprecision reduction

Example

# a model's weights stored as 32-bit floats can often be quantized

Common mistake: Assuming quantization always significantly hurts accuracy -- for many models the loss is small, and the speed/memory benefit is often well worth it.

What does reconstruction loss measure in a VAE?
  1. how similar two different training examples are

  1. there's no meaningful trade-off between them

  4. GANs always have simpler, more interpretable latent spaces

  1. blurriness is unrelated to the training objective
  2. the reconstruction loss (often pixel-wise) can encourage averaging over plausible outputs, producing smoother, less sharp results
  3. VAEs use a lower resolution by design
  4. GANs cannot produce blurry output under any circumstances

  3. tasks with no need for any latent representation

  2. normal data (seen during training) reconstructs well, while anomalous data the model never learned to represent reconstructs poorly, signaling anomaly

  1. using the latent space only for the original reconstruction task
  2. using the learned latent representations for other tasks, like clustering or as input features for another model
  3. discarding the latent space after training
  4. a synonym for the KL divergence term

  1. GANs always interpolate more smoothly
  2. a VAE's regularized, continuous latent space is specifically structured to support meaningful interpolation between points
  3. interpolation isn't possible with either architecture
  4. VAEs cannot generate new samples at all
What does 'compression' mean in the context of an autoencoder's latent space?
  1. losslessly storing the exact original data
  2. representing the essential information of the input in a lower-dimensional form, necessarily discarding some detail
  3. a synonym for the decoder specifically
  4. increasing the size of the representation

  1. the choice never matters in practice
  2. picking the architecture whose specific strengths (structured latent space vs sharper output) match your actual task requirements is a real design decision
  3. VAEs and GANs are always interchangeable with identical results
  4. only one of these architectures is ever used in real projects
What is the overall goal of a VAE's training objective?
  1. maximize reconstruction error
  2. balance accurate reconstruction with a well-regularized, structured latent space
  3. minimize the number of training epochs
  4. eliminate the need for a decoder
