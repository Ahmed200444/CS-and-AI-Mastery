01ARM assembly structure, syntax & directives

What you will learn

  • Read destination/source operand order
  • Use common assembler directives
  • Distinguish directives from CPU instructions

Explanation

ARM assembly source combines processor instructions with assembler directives. Most data-processing instructions place the destination first, followed by source operands. AREA, ENTRY, RN, EQU, ALIGN, SPACE, and END help the assembler organize code/data or define names; they are not operations executed by the CPU.

Key concepts

AREAENTRYENDRNEQUALIGNregister operands

Example

        AREA RESET, CODE, READONLY
        ENTRY
counter RN 0
limit   EQU 5
        MOV counter, #0
stop    B stop
        END
Common mistake: Treating assembler directives such as AREA or EQU as instructions executed by the ARM core.
02Registers, immediates, MOV & MVN

What you will learn

  • Move values between registers
  • Load simple immediate values
  • Explain MOV versus MVN

Explanation

Data-processing instructions work primarily on registers. MOV copies an operand into a destination register, while MVN writes the bitwise complement. Immediate operands use # in ARMASM syntax. Use the destination-first pattern when tracing instructions.

Key concepts

registerimmediateMOVMVNdestinationsource

Example

        MOV r0, #17
        MOV r1, r0
        MVN r2, r1
Common mistake: Reading MOV r0, r1 as copying r0 into r1.
03LDR/STR & ARM addressing modes

What you will learn

  • Load and store words/bytes/halfwords
  • Calculate effective addresses
  • Distinguish pre-indexed and post-indexed write-back

Explanation

ARM is a load-store architecture, so memory values move into registers before most data processing. LDR/STR transfer words, with byte and halfword variants. Addressing modes combine a base register with an offset; pre-indexing forms the address before access, while post-indexing uses the base first and updates it afterward.

Key concepts

LDRSTRLDRBSTRBLDRHSTRHpre-indexpost-index

Example

        MOV r2, #0x1000
        MOV r0, #17
        STR r0, [r2]
        MOV r0, #23
        STR r0, [r2, #4]
        LDR r1, [r2]
        LDR r3, [r2, #4]
        STR r3, [r2, #8]
        LDR r4, [r2], #4
Common mistake: Confusing the address in the base register with the data loaded from memory.
04Barrel shifter: LSL, LSR, ASR & ROR

What you will learn

  • Trace logical and arithmetic shifts
  • Explain rotate-right
  • Combine a shift with a data-processing instruction

Explanation

ARM can shift the second operand as part of many data-processing instructions. LSL shifts left, LSR shifts right with zero fill, ASR preserves the sign bit for signed values, and ROR rotates bits around. Combining ALU work with a shift is a characteristic ARM feature.

Key concepts

LSLLSRASRRORbarrel shifterOperand2

Example

        MOV r0, #7
        MOV r1, r0, LSL #1
        MOV r2, r1, LSR #2
        ADD r3, r0, r0, LSL #4
Common mistake: Assuming LSR and ASR are identical for values whose top bit is 1.
05CPSR flags & the S suffix

What you will learn

  • Explain N, Z, C, and V
  • Use the S suffix to update flags
  • Separate signed overflow from unsigned carry

Explanation

N reflects the result sign bit, Z indicates zero, C records carry/no-borrow information and shifted-out bits, and V reports signed arithmetic overflow. Many data-processing instructions update flags only when the S suffix is requested.

Key concepts

N flagZ flagC flagV flagCPSRS suffix

Example

        MOV  r0, #5
        SUBS r1, r0, #5
        MOVS r2, #-1
Common mistake: Treating C and V as the same condition.
06CMP, CMN, TST, TEQ & conditional execution

What you will learn

  • Use comparison instructions to set flags
  • Choose a condition code from flag results
  • Explain conditional instruction execution

Explanation

CMP behaves like subtraction for flag setting, CMN like addition, TST like bitwise AND, and TEQ like XOR. They update flags without keeping a normal destination result. Conditional suffixes such as EQ or NE make an instruction execute only when its flag condition is satisfied.

Key concepts

CMPCMNTSTTEQEQNELTGT

Example

        MOV r0, #2
        CMP r0, #2
        MOVEQ r1, #1
        MOVNE r1, #0
        TST r0, #2
Common mistake: Expecting CMP to store a normal subtraction result.
07Logical operations & bit manipulation

What you will learn

  • Apply bitwise AND/OR/XOR
  • Clear selected bits with BIC
  • Build and reason about masks

Explanation

AND keeps bits selected by a mask, ORR sets selected bits, EOR performs XOR, and BIC clears bits selected by the second operand. These operations are central to packed flags and device/control registers.

Key concepts

ANDORREORBICMVNbit mask

Example

        MOV r0, #0x0F
        MOV r1, #0x03
        AND r2, r0, r1
        ORR r3, r0, #0x10
        EOR r4, r0, r1
        BIC r5, r0, #0x03
Common mistake: Using arithmetic intuition for bit masks instead of tracing each bit position.
08Arithmetic instructions: ADD, ADC, SUB, SBC, RSB & RSC

What you will learn

  • Trace three-operand arithmetic
  • Explain add/subtract with carry
  • Use reverse subtraction correctly

Explanation

ARM arithmetic instructions typically use a destination and two input operands. ADD and SUB perform basic arithmetic; ADC and SBC include carry state for multiword arithmetic. RSB reverses subtraction order, useful when the desired calculation is operand2 minus operand1.

Key concepts

ADDADCSUBSBCRSBRSCcarry

Example

        MOV r1, #9
        MOV r2, #4
        ADD r0, r1, r2
        SUB r3, r1, r2
        RSB r4, r1, r2
Common mistake: Applying normal SUB operand order to RSB.
09Branches, if/else & loops

What you will learn

  • Branch to labels
  • Translate decisions into branches
  • Trace while and do-while loops

Explanation

Branch instructions change control flow by loading a new PC value. Labels identify targets. Conditional branches combine flag tests with control flow, which implements if/else and loops. Testing before or after the body distinguishes pre-test and post-test loops.

Key concepts

BBLBXlabelwhile loopdo-while

Example

j       RN 0
        MOV j, #3
loop    CMP j, #0
        BLT done
        SUB j, j, #1
        B loop
done    B done
Common mistake: Forgetting that a loop must modify the state used by its termination condition.
10LDM/STM, PUSH/POP & the runtime stack

What you will learn

  • Transfer multiple registers
  • Explain multiple-addressing modes
  • Trace stack growth and PUSH/POP

Explanation

LDM and STM move multiple registers between registers and memory. Addressing-mode suffixes specify increment/decrement and before/after behavior. PUSH and POP are stack-oriented aliases using R13/SP; in the convention shown in the lectures, PUSH corresponds to STMDB and POP to LDMIA, so the stack grows toward lower addresses.

Key concepts

LDMSTMPUSHPOPSPR13IAIBDADB

Example

        LDR r3, =0x11111111
        LDR r4, =0x22222222
        PUSH {r3, r4}
        POP  {r5, r6}
Common mistake: Assuming textual register-list order controls memory ordering.
11Subroutines, BL/BX LR & parameter passing

What you will learn

  • Call and return from a subroutine
  • Preserve registers across calls
  • Compare register, memory-block, and stack parameter passing

Explanation

BL branches while saving a return address in LR/R14. A simple return can use BX LR. Subroutines preserve state according to the calling convention. Parameters can be passed in registers, through a referenced memory block, or on the stack; stack-based access must account for values pushed on entry.

Key concepts

BLBX LRLRcallee stateparametersstack

Example

main    MOV r0, #5
        BL double
        B stop

double  PUSH {r1}
        ADD r1, r0, r0
        MOV r0, r1
        POP {r1}
        BX lr
stop    B stop
Common mistake: Calling another function without protecting LR when the current function still needs its own return address.
12Exceptions, interrupts, vectors & SVC

What you will learn

  • List major classic ARM exception types
  • Trace automatic exception entry
  • Explain vector dispatch and return
  • Distinguish IRQ, FIQ, and SVC

Explanation

On a classic ARM exception, CPSR is copied to the relevant SPSR, the processor changes mode, a return address is stored in mode-specific LR, and PC goes to an exception vector. The vector dispatches to a handler, which returns using the exception-appropriate sequence. SVC deliberately requests a privileged OS service.

Key concepts

exceptionSPSRLR_modevector tableIRQFIQSVC

Example

0x00  Reset
0x04  Undefined instruction
0x08  SVC
0x0C  Prefetch abort
0x10  Data abort
0x18  IRQ
0x1C  FIQ
Common mistake: Using the same unadjusted LR return sequence for every exception type.
