01Resume fundamentals: structure & content

What you will learn

  • Structure a resume that a recruiter can scan in under 10 seconds
  • Explain how scannable structure changes the behavior, result, or engineering decision in a concrete example
  • Connect scannable structure with outcome-focused bullets and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

A resume gets scanned, not read, in the first pass — often under 10 seconds. Structure matters as much as content: a clear header, a tight skills section, and experience/projects described with concrete outcomes ('reduced query time by 40%') rather than vague duties ('worked on backend features').

Key concepts

scannable structureoutcome-focused bulletsthe 10-second testbullet is strongestresume bullet

Example

# weak: 'Worked on the backend of a web application'
# strong: 'Built a REST API serving 10k+ daily requests, reducing average response time by 35%'
Common mistake: Listing job duties instead of outcomes — 'responsible for X' tells a recruiter what you were assigned, not what you actually accomplished or how well you did it.

Explanation

A recruiter or engineer will often click through to GitHub before or during an interview loop — a profile with pinned, well-named repositories, clear READMEs, and a sensible commit history (from the Git & GitHub track) reads as someone who ships real, maintained work.

Key concepts

pinned repositoriesREADME qualitycommit history as evidencepin specific repositoriescommit history

Example

# pin your 4-6 BEST repos explicitly (GitHub lets you choose)
# make sure each pinned repo has: a real README, a working demo/screenshot if applicable,
# and reasonably recent, real commit activity -- not a single 'initial commit'
Common mistake: Leaving GitHub's default repo ordering (most recently updated) instead of deliberately pinning your strongest work — a reviewer may see an old throwaway script before your best project.

Explanation

Before submitting: does every bullet show an outcome, not just a duty? Does it mirror the target job description's key terms?

Key concepts

pre-submission checklistexternal reviewsystematic final passreview checklist is best used

Example

# a genuinely useful pre-submit checklist:
# [ ] every bullet has a measurable/concrete outcome
# [ ] key terms from the job description appear naturally
# [ ] simple, ATS-safe formatting
# [ ] zero typos (read aloud + a second reviewer)

Common mistake: Submitting a resume immediately after writing it with no second pass or outside reviewer — a fresh set of eyes catches errors and unclear phrasing the writer has become blind to.

Knowledge checks

A resume bullet is strongest when it shows:
  1. a list of duties
  2. a concrete, measurable outcome
  3. as many buzzwords as possible
  4. the exact hours worked
ATS optimization mainly means:
  1. adding more graphics
  2. using simple, parseable formatting and matching job-description keywords
  3. writing a longer resume
  4. using a colorful template
A strong portfolio generally favors:
  1. as many projects as possible, regardless of completion
  2. 2-3 polished, well-documented projects over many unfinished ones
  3. projects with no README
  4. private repositories only
Tailoring a resume per application primarily means:
  1. rewriting it completely from scratch every time
  2. adjusting emphasis and keywords to match the specific job description
  3. making it longer
  4. removing all prior experience
The resume review checklist is best used:
  1. only once, when first written
  2. as a final, repeatable gate before every submission
  3. only for the first application
  4. after the interview is over
What does 'the 10-second test' for a resume mean?
  1. how long it takes to print
  2. whether a reader can grasp your key qualifications in a very quick skim
  3. the required font size
  4. how long the interview should last
Why prefer outcome-focused bullets over responsibility-focused ones?
  1. outcomes are less important than responsibilities
  2. outcomes demonstrate impact and results, which is more compelling than just listing duties performed
  3. responsibility-focused bullets are always better
  4. this distinction doesn't matter to recruiters
What does ATS stand for?
  1. Automated Talent Screening
  2. Applicant Tracking System
  3. Advanced Text Scanner
  4. Assessment Tracking Software
Why does simple, parseable formatting matter for ATS?
  1. formatting has no effect on ATS
  2. complex formatting (tables, images, unusual fonts) can prevent an ATS from correctly extracting your information
  3. ATS systems only reject resumes with too much formatting
  4. ATS systems always parse every format identically
What does keyword matching in ATS systems look for?
  1. only the applicant's name
  2. terms from the job description appearing in your resume, since many ATS systems rank or filter based on this
  3. a synonym for font matching
  4. only years of experience
Why prioritize evidence over claims in a portfolio?
  1. claims are always more persuasive
  2. concrete evidence (real projects, code, outcomes) is more convincing than unsupported self-description
  3. evidence and claims are equally weighted always
  4. portfolios shouldn't include evidence
What does project curation for a portfolio mean?
  1. including every project you've ever done
  2. selecting and presenting your strongest, most relevant projects rather than everything indiscriminately
  3. curation only matters for design portfolios
  4. avoiding any project selection at all
Why does README quality matter for a GitHub portfolio?
  1. READMEs are rarely read
  2. a clear README helps a reviewer quickly understand what a project does and why it matters, without reading all the code
  3. READMEs only matter for very large projects
  4. README quality has no bearing on how a project is perceived
What does commit history 'as evidence' mean?
  1. commit history is irrelevant to evaluators
  2. a consistent, meaningful commit history can demonstrate real, sustained work and good practices, not just a final code dump
  3. commit messages are never checked by anyone
  4. only the number of commits matters, not their content
Why optimize a LinkedIn headline?
  1. headlines have no effect on visibility
  2. a clear, keyword-relevant headline improves how easily recruiters find and understand your profile in search
  3. LinkedIn headlines are purely decorative
  4. only your most recent job title should ever appear there
What tension exists between searchability and readability on LinkedIn?
  1. there's no real tension
  2. packing in keywords for search can make a profile awkward to read for actual humans, requiring a balance
  3. searchability and readability are the same thing
  4. only readability matters, search behavior is irrelevant
Why tailor a resume per application rather than sending one generic version?
  1. tailoring wastes time with no real benefit
  2. different roles emphasize different skills, and reflecting the specific job's priorities improves relevance and ATS matching
  3. recruiters never notice tailored vs generic resumes
  4. one generic resume is always equally effective everywhere
What does bullet reordering across applications accomplish?
  1. nothing meaningful
  2. surfacing your most relevant experience for THIS specific role near the top, rather than a fixed generic order
  3. reordering has no effect on how resumes are read
  4. bullets should never be reordered
Why are typos and inconsistencies particularly damaging on a resume?
  1. they have minimal real impact
  2. they can signal carelessness to a reviewer, even if unrelated to your actual skills, in a document meant to represent your best work
  3. typos are expected and ignored by recruiters
  4. consistency doesn't matter as long as content is accurate
Why avoid buzzwords without supporting evidence?
  1. buzzwords always strengthen a resume
  2. unsupported buzzwords ('detail-oriented', 'hard worker') are vague and unconvincing without concrete evidence backing them up
  3. evidence is unnecessary if the buzzword sounds impressive
  4. buzzwords are required by ATS systems
Why maintain length discipline on a resume?
  1. longer resumes are always better
  2. excessive length can bury your strongest points and signal poor prioritization, especially early in a career
  3. length has no effect on how a resume is received
  4. resumes should always be exactly one specific length regardless of experience
Why get external review of your resume before submitting it?
  1. external review is unnecessary if you're confident
  2. a fresh perspective often catches unclear phrasing, typos, or missing context you're too close to notice yourself
  3. external reviewers are never more effective than self-review
  4. external review can only be done by professional resume writers
Why use a systematic final-pass checklist before submitting a resume?
  1. checklists are unnecessary busywork
  2. having a systematic pass reduces the chance of missing an obvious formatting, spelling, or content issue right before it matters most
  3. checklists guarantee a resume gets an interview
  4. final review has no measurable benefit
Why include specific, quantified numbers in resume achievements?
  1. numbers are decorative and don't add real value
  2. specific numbers make claims verifiable-seeming and memorable, distinguishing them from vague, unsupported claims
  3. numbers are only relevant for finance roles
  4. vague claims are always equally persuasive
What is a strong example of quantifying an achievement?
  1. 'Worked on the checkout process'
  2. 'Reduced cart abandonment from 68% to 51% by redesigning the checkout flow'
  3. 'Responsible for checkout'
  4. 'Helped with checkout improvements'
Why does 'showing, not just telling' matter in a portfolio?
  1. telling is always more effective than showing
  2. concrete demonstrations (real code, live projects, documented outcomes) are more convincing than simply asserting your skills
  3. showing and telling are equally weak approaches
  4. portfolios should rely entirely on self-description
Why pin specific repositories on a GitHub profile?
  1. pinning has no effect on how a profile is viewed
  2. pinned repos are the first things a visitor sees, so they should showcase your strongest, most representative work
  3. GitHub automatically selects the best repos to feature
  4. pinning is only relevant for large open-source projects
What is a risk of over-relying on ATS keyword stuffing?
  1. there's no risk, more keywords are always better
  2. excessive, unnatural keyword stuffing can make a resume read poorly for the human reviewer who eventually sees it, even if it passes ATS
  3. ATS systems always penalize keyword usage entirely
  4. keyword stuffing improves readability
Why might recruiter search behavior matter when optimizing a LinkedIn profile?
  1. recruiters never search LinkedIn directly
  2. understanding what terms recruiters actually search for helps you include those terms naturally where they'll be found
  3. search behavior is completely unpredictable and not worth considering
  4. recruiter search only matters for entry-level roles
Why is a resume's structure (clear sections, scannable layout) important?
  1. structure has no real effect on how a resume is received
  2. a scannable structure helps a time-pressed reviewer quickly find the information most relevant to their decision
  3. structure only matters for creative-industry resumes
  4. unstructured resumes are equally effective
