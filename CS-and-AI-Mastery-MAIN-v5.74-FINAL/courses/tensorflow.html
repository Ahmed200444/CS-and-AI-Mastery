  • Connect tensor with eager execution and predict what changes when one assumption changes

Explanation

TensorFlow tensors work much like PyTorch's or NumPy's arrays: multi-dimensional, typed, and shape-checked.

Key concepts

tensoreager executiongraph mode

Example

import tensorflow as tf
x = tf.constant([[1., 2.], [3., 4.]])
print(x.shape)             # (2, 2)
y = tf.matmul(x, x)        # eager execution -- runs immediately, prints real values
Common mistake: Assuming TensorFlow still requires building an explicit static graph before running anything, as in TF1 — TF2's eager-by-default execution is deliberately much closer to normal, immediately-debuggable Python.
02Building a model with the Keras Sequential API

What you will learn

  • Define a simple model by stacking layers with the Sequential API
  • Explain how Sequential API changes the behavior, result, or engineering decision in a concrete example
  • Connect Sequential API with layer stacking and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

The Sequential API is the simplest way to build a model: a straight stack of layers, each feeding directly into the next, declared in order. It's fast to write and read, but only fits models with a single input, single output, and no branching or shared layers — for anything more complex, the Functional API (next lesson) is needed.

Key concepts

Sequential APIlayer stackingsingle input/output limitation

Example

from tensorflow import keras
model = keras.Sequential([
    keras.layers.Dense(128, activation='relu', input_shape=(784,)),
    keras.layers.Dense(10, activation='softmax'),
])
Common mistake: Trying to force a model with multiple inputs or a skip-connection into the Sequential API — this API genuinely can't express that; recognize when you need the Functional API instead.
03The Keras Functional API for flexible architectures

What you will learn

  • Build a model with multiple inputs, outputs, or branching using the Functional API
  • Explain how Functional API changes the behavior, result, or engineering decision in a concrete example
  • Connect Functional API with multi-input/output models and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

The Functional API treats layers as callable functions applied to explicit tensor inputs, letting you build graphs Sequential can't express: multiple inputs, multiple outputs, or branches that merge back together (like a skip connection).

Key concepts

Functional APImulti-input/output modelsexplicit graph wiring

Example

inputs = keras.Input(shape=(784,))
x = keras.layers.Dense(128, activation='relu')(inputs)
outputs = keras.layers.Dense(10, activation='softmax')(x)
model = keras.Model(inputs=inputs, outputs=outputs)
Common mistake: Defaulting to the Functional API's added complexity for a simple single-path model — Sequential is simpler and sufficient whenever your architecture genuinely has no branching.
04tf.data pipelines for real datasets

What you will learn

  • Build an efficient input pipeline with tf.data
  • Explain how tf.data.Dataset changes the behavior, result, or engineering decision in a concrete example
  • Connect tf.data.Dataset with shuffle/batch/map/prefetch and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

`tf.data.Dataset` builds an efficient, composable input pipeline: load data, apply transformations (shuffle, batch, map a preprocessing function, prefetch), and feed it to training — designed so data loading/preprocessing can overlap with GPU computation instead of blocking it, which matters a lot for real dataset sizes.

Key concepts

tf.data.Datasetshuffle/batch/map/prefetchpipeline overlapprefetchbatch and prefetch

Example

dataset = tf.data.Dataset.from_tensor_slices((images, labels))
dataset = dataset.shuffle(1000).batch(32).map(preprocess_fn).prefetch(tf.data.AUTOTUNE)
for batch_images, batch_labels in dataset: ...
Common mistake: Loading and preprocessing an entire large dataset eagerly into memory up front instead of building a lazy tf.data pipeline — this doesn't scale to real dataset sizes and wastes the overlap opportunity prefetch provides.
05Training with model.fit and custom training loops

What you will learn

  • Train a Keras model with model.fit, and know when a custom training loop is needed instead
  • Explain how model.compile/fit changes the behavior, result, or engineering decision in a concrete example
  • Connect model.compile/fit with tf.GradientTape and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

For standard cases, `model.compile()` (specifying optimizer, loss, metrics) followed by `model.fit()` handles the entire training loop for you — batching, gradient updates, validation, all in one call.

Key concepts

model.compile/fittf.GradientTapewhen to go custommodel.compile()custom training loop

Example

model.compile(optimizer='adam', loss='sparse_categorical_crossentropy', metrics=['accuracy'])
history = model.fit(train_dataset, validation_data=val_dataset, epochs=10)

# custom loop, when fit() isn't flexible enough:
with tf.GradientTape() as tape:
    predictions = model(x, training=True)
    loss = loss_fn(y, predictions)
grads = tape.gradient(loss, model.trainable_variables)
optimizer.apply_gradients(zip(grads, model.trainable_variables))
Common mistake: Reaching for a custom GradientTape loop by default 'for control' when model.fit() with callbacks would handle the case perfectly well — the built-in loop covers the large majority of real training needs.

Explanation

The same debugging discipline from the PyTorch track applies here: check shapes explicitly at each step, try to overfit a tiny subset of data first (if that fails, the bug is in your code), and inspect actual data batches rather than assuming preprocessing worked.

Key concepts

shape debuggingoverfit-small-subset testeager execution for debugging

Example

# same 'overfit 10 examples' test as PyTorch:
# if the model can't drive loss near zero on 10 examples, the bug is in your code
# (wrong loss, bad labels, frozen layers) -- not dataset difficulty or model capacity
Common mistake: Assuming a non-learning model just needs more epochs or a bigger model before ruling out an actual bug with the fast small-subset overfit test.
07Callbacks & training monitoring

What you will learn

  • Use Keras callbacks to monitor and control training automatically
  • Explain how EarlyStopping changes the behavior, result, or engineering decision in a concrete example
  • Connect EarlyStopping with ModelCheckpoint and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

Callbacks hook into the training loop at specific points (end of each epoch, when a metric stops improving) without you writing manual loop logic: EarlyStopping halts training when validation loss stops improving (fighting overfitting automatically), ModelCheckpoint saves the best-performing version seen so far.

Key concepts

EarlyStoppingModelCheckpointTensorBoard

Example

callbacks = [
    keras.callbacks.EarlyStopping(patience=3, restore_best_weights=True),
    keras.callbacks.ModelCheckpoint('best_model.keras', save_best_only=True),
]
model.fit(train_dataset, validation_data=val_dataset, epochs=50, callbacks=callbacks)
Common mistake: Manually watching a training log and stopping by hand when it looks like it's overfitting — EarlyStopping automates exactly this, more reliably and reproducibly.

TensorFlow's native format saves the full model (architecture AND weights) in one step, simpler than PyTorch's weights-only convention.

Example

model.save('my_model.keras')                       # full model: architecture + weights

Knowledge checks

TF2's default execution mode is:
  1. graph mode only
  2. eager execution
  3. no execution, just definition
  4. distributed mode only
The Keras Functional API is needed over Sequential when a model has:
  1. exactly one input and one output in a straight stack
  2. multiple inputs, multiple outputs, or branching
  3. fewer than 3 layers
  4. no activation functions
tf.data's prefetch is used to:
  1. reduce model size
  2. overlap data loading/preprocessing with GPU computation
  3. skip validation
  4. increase batch size automatically
EarlyStopping is used to:
  1. speed up each epoch
  2. stop training automatically when validation performance stops improving
  3. increase the learning rate
  4. save disk space only
TensorFlow Lite is primarily used for:
  1. training large models faster
  2. deploying models to mobile/edge devices
  3. running models in a browser
  4. distributed multi-GPU training
What is eager execution in TensorFlow?
  1. a mode where operations execute immediately and can be inspected directly, unlike building a static graph first
  2. a way to skip training entirely
  3. a synonym for graph mode
  4. only available in TensorFlow 1.x
What is graph mode in TensorFlow?
  1. identical to eager execution
  2. a mode where operations are compiled into a computation graph, often for performance, rather than executing immediately
  3. a debugging-only mode
  4. a synonym for tf.data
What does the Keras Sequential API let you build?
  1. only multi-input models
  2. a model as a simple linear stack of layers, one input and one output
  3. models with custom training loops only
  4. models with no layers at all
What is a limitation of the Sequential API?
  1. it has no limitations
  2. it only supports a single linear stack, not multiple inputs/outputs or non-linear layer connections
  3. it can't be used for image models
  4. it's slower than the Functional API always
What does the Functional API allow that Sequential doesn't?
  1. nothing extra
  2. building models with multiple inputs/outputs and explicit, non-linear graph wiring between layers
  3. training without a loss function
  4. skipping compilation entirely
What does 'explicit graph wiring' mean in the Functional API?
  1. layers are connected automatically with no control
  2. you explicitly specify how each layer's output connects to the next layer's input, allowing flexible architectures
  3. wiring refers only to hardware connections
  4. this term applies only to Sequential models
What is tf.data.Dataset used for?
  1. defining a model's layers
  2. building efficient, scalable input pipelines for feeding data into a TensorFlow model
  3. computing gradients
  4. saving a trained model
What does .prefetch() in a tf.data pipeline help with?
  1. it has no performance benefit
  2. overlapping data preparation with model execution, so the GPU/CPU isn't left waiting on data loading
  3. it deletes unused data
  4. it only affects the final saved model size
What does model.compile() configure before training?
  1. the model's saved file format
  2. the optimizer, loss function, and metrics to use during training
  3. the dataset's batch size only
  4. the GPU device to use
What does model.fit() do?
  1. only evaluates a model, without training it
  2. runs the training loop using the compiled configuration and provided data
  3. saves the model to disk
  4. builds the Keras Functional API graph
When would you write a custom training loop instead of using model.fit()?
  1. custom loops are never necessary
  2. when you need finer control over the training process than model.fit()'s built-in loop provides
  3. model.fit() can't be used with Keras models
  4. custom loops are required for every project
What does tf.GradientTape do?
  1. saves the model to disk
  2. records operations during a forward pass so gradients can be computed for a custom training loop
  3. builds the Sequential API model
  4. loads a saved dataset
Why might shape debugging be common in TensorFlow, similar to other deep learning frameworks?
  1. shapes are never a source of errors in TensorFlow
  2. mismatched tensor shapes between layers is a frequent, sometimes cryptic source of runtime errors
  3. TensorFlow automatically resolves all shape mismatches
  4. this only applies to PyTorch, not TensorFlow
What is the 'overfit-small-subset test' used for?
  1. measuring final production performance
  2. sanity-checking that a model architecture and pipeline can learn at all, by trying to overfit a small subset of data
  3. evaluating a fully-trained model on held-out data
  4. a required step before every single training run
Why is eager execution useful specifically for debugging?
  1. it isn't useful for debugging
  2. it lets you inspect intermediate values directly as code runs, rather than needing to run a full compiled graph first
  3. eager execution disables all error messages
  4. debugging requires disabling eager execution
What does the EarlyStopping callback do?
  1. always trains for a fixed number of epochs regardless of performance
  2. stops training automatically when a monitored metric (like validation loss) stops improving
  3. saves the model to disk periodically
  4. only works with the Functional API
What does the ModelCheckpoint callback do?
  1. stops training early
  2. saves the model (or its weights) periodically during training, often keeping the best-performing version
  3. monitors GPU temperature
  4. builds the Functional API graph
What is TensorBoard used for?
  1. compiling a model faster
  2. visualizing training metrics, model graphs, and other diagnostics over time
  3. replacing the need for a loss function
  4. only for saving models to disk
What does model.save() typically preserve?
  1. only the training data
  2. the model's architecture, weights, and training configuration, so it can be reloaded and used later
  3. only the optimizer's internal state
  4. nothing usable for future inference
What is TensorFlow Serving used for?
  1. training models faster
  2. deploying trained TensorFlow models for scalable, production inference serving
  3. visualizing training metrics
  4. only for mobile deployment
What is TensorFlow Lite designed for?
  1. large-scale cloud training
  2. deploying models to mobile and embedded devices with resource constraints
  3. visualizing model graphs
  4. replacing tf.data pipelines
What is TensorFlow.js designed for?
  1. training models on a server cluster
  2. running TensorFlow models directly in the browser or Node.js using JavaScript
  3. only visualizing metrics
  4. mobile-only deployment
Why might using categorical_crossentropy with integer labels cause a bug?
  1. it never causes any issue
  2. categorical_crossentropy expects one-hot encoded labels, while integer labels need sparse_categorical_crossentropy instead
  3. integer labels are always converted automatically with no configuration needed
  4. this only matters for the Functional API
Why choose an output activation like softmax for multi-class classification?
  1. softmax has no specific purpose here
  2. softmax converts raw outputs into a valid probability distribution across classes, summing to 1
  3. softmax is only used for regression tasks
  4. any activation function works identically for this purpose
Why batch and prefetch a tf.data pipeline rather than feeding data one example at a time?
  1. batching and prefetching have no performance benefit
  2. they let the pipeline prepare the next batch while the current one is being processed, improving throughput and utilizing hardware more efficiently
  3. batching only matters for very small datasets
  4. prefetching disables GPU acceleration
