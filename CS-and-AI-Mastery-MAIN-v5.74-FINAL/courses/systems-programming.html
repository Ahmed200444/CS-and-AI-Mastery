⚙️ Systems Programming

Python systems programming: files, processes, threads, IPC, sockets, synchronization, and operating-system resource management.

01Memory, lifetime & resource ownership

What you will learn

  • Distinguish object lifetime concepts
  • Explain deterministic cleanup
  • Identify resource leaks

Explanation

Systems programming makes resource lifetime explicit. Stack storage typically follows scope and call lifetime, while heap objects can outlive the function that created them.

Key concepts

stackheaplifetimeownershipcontext manager

Example

from contextlib import contextmanager

@contextmanager
def resource(name):
    print("open", name)
    try:
        yield name
    finally:
        print("close", name)

with resource("demo") as handle:
    print("using", handle)
Common mistake: Acquiring files, locks, sockets, or other resources without a guaranteed cleanup path.
02References, mutability & ownership

What you will learn

  • Explain reference semantics
  • Avoid accidental shared mutation
  • Choose shallow or deep copying intentionally

Explanation

A reference identifies an existing object rather than copying its full contents. With mutable objects, two names can refer to the same object, so a change through one reference can be observed through the other.

Key concepts

referencemutabilityidentitycopyinggarbage collection

Example

import copy
original = {"items": [1, 2]}
clone = copy.deepcopy(original)
clone["items"].append(3)
print(original, clone)
Common mistake: Confusing assignment, shallow copy, and deep copy.
03Files, descriptors & OS boundaries

What you will learn

  • Explain file descriptors
  • Handle file operations safely
  • Use context managers around resources

Explanation

Operating systems expose files and many devices through descriptor-like handles. A program asks the kernel to read, write, open, close, or otherwise operate on those resources through system-call boundaries.

Key concepts

file descriptorreadwriteerrnosystem call

Example

import os, tempfile
fd, path = tempfile.mkstemp()
os.write(fd, b"hello")
os.lseek(fd, 0, 0)
print(os.read(fd, 5).decode())
os.close(fd)
os.unlink(path)
Common mistake: Assuming every read/write completes exactly as requested or ignoring OS errors.
04Processes & program execution

What you will learn

  • Explain process isolation
  • Launch child processes
  • Track exit status and output

Explanation

A process is an executing program with its own address space, resources, environment, and operating-system identity. Starting a subprocess creates a separate execution context; the parent can pass arguments/environment, capture output, and inspect the exit status.

Key concepts

processsubprocessexit statusenvironmentisolation

Example

import subprocess
result = subprocess.run(["python", "-c", "print(6 * 7)"], capture_output=True, text=True)
print(result.returncode, result.stdout.strip())
Common mistake: Launching commands without checking the exit status or safely separating command arguments.
05Threads, races & synchronization

What you will learn

  • Identify shared-state races
  • Protect shared state
  • Explain lock scope

Explanation

Threads share process memory, which makes communication cheap but also allows data races when multiple threads access shared mutable state without safe coordination. Locks protect critical sections, condition variables let threads wait for state changes, and queues often provide a clearer ownership boundary for work.

Key concepts

threaddata racelockqueuecondition

Example

from threading import Lock
lock = Lock()
total = 0
with lock:
    total += 1
print(total)
Common mistake: Sharing mutable state between threads without a synchronization plan.
06IPC: pipes, sockets & shared memory

What you will learn

  • Compare IPC mechanisms
  • Design a simple message protocol
  • Handle ownership and failure

Explanation

Inter-process communication moves information across process boundaries. Pipes provide a byte stream commonly used between related processes, sockets support local or networked communication, and shared memory can avoid copying but requires careful synchronization and a defined memory layout.

Key concepts

IPCpipesocketshared memoryprotocol

Example

from multiprocessing import Pipe
left, right = Pipe()
left.send({"type": "job", "id": 7})
print(right.recv())
Common mistake: Sending bytes through a pipe or socket without a framing/protocol rule.
07Concurrency design & worker pools

What you will learn

  • Bound concurrency
  • Use a task queue
  • Reason about backpressure

Explanation

Worker pools bound concurrency by keeping a controlled number of workers that take tasks from a queue. This is different from starting an unlimited thread or process for every request.

Key concepts

worker pooltask queuebackpressurefuturethroughput

Example

from concurrent.futures import ThreadPoolExecutor

def work(value):
    return value * value

with ThreadPoolExecutor(max_workers=3) as pool:
    print(list(pool.map(work, [2, 3, 4, 5])))
Common mistake: Creating unbounded workers or queues.
08Profiling & systems debugging

What you will learn

  • Measure memory behavior
  • Read profiler evidence
  • Optimize after measuring

Explanation

Profiling and debugging answer different questions. A debugger helps inspect control flow and state around a correctness failure, while a profiler measures where time or memory is actually spent.

Key concepts

tracemallocdebuggerprofilingloggingbenchmark

Example

import time
start = time.perf_counter()
result = sum(i * i for i in range(10000))
elapsed = time.perf_counter() - start
print(result, round(elapsed, 6))
Common mistake: Optimizing from intuition before measuring.
