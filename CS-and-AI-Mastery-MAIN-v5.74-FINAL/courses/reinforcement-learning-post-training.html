01The reinforcement-learning interaction loop

What you will learn

  • Explain how an RL agent learns from interaction rather than labeled targets.
  • Explain how agent changes the behavior, result, or engineering decision in a concrete example
  • Connect agent with environment and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

Reinforcement learning studies sequential decisions. At each step an agent observes state or observation, chooses an action, receives a reward, and reaches a new state.

Key concepts

agentenvironmentrewardtrajectory

Example

trajectory=[("s0","right",0),("s1","right",0),("goal","stop",1)]
print("return",sum(r for _,_,r in trajectory))
Common mistake: Treating reward as a label for each action ignores delayed effects and can encourage behavior that looks locally good but fails the long-term task.
02MDPs, states, actions & the Markov property

What you will learn

  • Specify an RL task as an MDP and identify when the observation is not truly Markov.
  • Explain how MDP changes the behavior, result, or engineering decision in a concrete example
  • Connect MDP with state and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

An MDP formalizes states, actions, transition probabilities, reward function, and discount factor. The Markov property says the current state contains the information needed to predict the distribution of the next state given an action; history should not add information once state is known.

Key concepts

MDPstatetransitionMarkov property

Example

mdp={"states":[0,1,2],"actions":["left","right"],"gamma":0.99}
print(mdp)
Common mistake: Calling any sensor reading “the state” can violate the Markov assumption if past information is required to predict what happens next.
03Returns, discounting & reward design

What you will learn

  • Compute discounted return and reason about reward design incentives.
  • Explain how return changes the behavior, result, or engineering decision in a concrete example
  • Connect return with discount factor and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

The return is the cumulative future reward an agent tries to maximize. Discounting with gamma gives nearer rewards more weight and keeps infinite-horizon sums well behaved.

Key concepts

returndiscount factorreward shaping

Example

rewards=[0,1,2]; gamma=.9
G=sum((gamma**t)*r for t,r in enumerate(rewards))
print(round(G,3))
Common mistake: Adding a convenient shaping reward can create reward hacking where the agent maximizes the proxy instead of the real objective.
04Value functions: V(s) and Q(s,a)

What you will learn

  • Interpret value functions as expected future return under a policy.
  • Explain how state value changes the behavior, result, or engineering decision in a concrete example
  • Connect state value with action value and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

Vπ(s) is the expected return starting from state s and following policy π. Qπ(s,a) additionally conditions on taking action a first.

Key concepts

state valueaction valuepolicy

Example

Q={"safe":1.2,"risky":0.8}
print("greedy action",max(Q,key=Q.get))
Common mistake: A value estimate is not an immediate reward; it summarizes expected future return and therefore depends on downstream behavior.
05Bellman equations & bootstrapping

What you will learn

  • Explain how values relate recursively to reward plus next-state value.
  • Explain how Bellman equation changes the behavior, result, or engineering decision in a concrete example
  • Connect Bellman equation with bootstrapping and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

Bellman equations express value as immediate reward plus discounted expected value of what follows. This recursive structure enables dynamic programming and temporal-difference learning.

Key concepts

Bellman equationbootstrappingbackup

Example

reward=1; gamma=.9; next_value=4
value=reward+gamma*next_value
print(value)
Common mistake: Bootstrapping from a badly biased value target can spread that bias through many states, so stability and target construction matter.
06Dynamic programming: policy evaluation & iteration

What you will learn

  • Solve small known MDPs when transition and reward models are available.
  • Explain how policy evaluation changes the behavior, result, or engineering decision in a concrete example
  • Connect policy evaluation with policy improvement and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

Dynamic programming repeatedly applies Bellman backups using a known environment model. Policy evaluation estimates values for a fixed policy; policy improvement chooses better actions using those values; policy iteration alternates both.

Key concepts

policy evaluationpolicy improvementvalue iteration

Example

V={0:0.0,1:0.0}
for _ in range(5):
    V[0]=1+.9*V[1]; V[1]=2+.9*V[0]
print(V)
Common mistake: Dynamic programming assumes access to transition probabilities and rewards; applying it directly to an unknown real environment is usually impossible.
07Monte Carlo learning

What you will learn

  • Estimate values from complete sampled episodes without an environment model.
  • Explain how Monte Carlo changes the behavior, result, or engineering decision in a concrete example
  • Connect Monte Carlo with episode and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

Monte Carlo methods wait until an episode ends, compute the observed return, and use it as a target. They do not bootstrap and need no transition model, making them conceptually simple and unbiased with enough representative samples.

Key concepts

Monte Carloepisodesample return

Example

returns=[3,5,4,6]
print("MC estimate",sum(returns)/len(returns))
Common mistake: Treating one noisy episode return as a reliable value estimate produces unstable learning; Monte Carlo relies on averaging many samples.
08Temporal-difference learning

What you will learn

  • Update a value estimate before an episode finishes.
  • Explain how TD learning changes the behavior, result, or engineering decision in a concrete example
  • Connect TD learning with TD error and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

Temporal-difference learning combines sampling with bootstrapping. TD(0) updates V(s) toward r + γV(s′) after each transition, using the TD error as the learning signal.

Key concepts

TD learningTD errorbootstrapping

Example

V=2.0; reward=1; next_v=3; gamma=.9; alpha=.1
td=reward+gamma*next_v-V
V += alpha*td
print(V)
Common mistake: Using too large a learning rate can make bootstrapped value estimates oscillate or diverge instead of settling.
09SARSA & Q-learning

What you will learn

  • Contrast on-policy and off-policy TD control.
  • Explain how SARSA changes the behavior, result, or engineering decision in a concrete example
  • Connect SARSA with Q-learning and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

SARSA updates Q using the next action actually chosen by the current behavior policy, so it is on-policy. Q-learning updates toward the maximum next-action value, learning a greedy target policy while behavior may still explore, so it is off-policy.

Key concepts

SARSAQ-learningon-policyoff-policy

Example

q_sa=1; r=0; gamma=.9; q_next_actual=.5; q_next_best=1.2
print("SARSA target",r+gamma*q_next_actual,"Q target",r+gamma*q_next_best)
Common mistake: Assuming on-policy and off-policy methods behave identically can hide important safety differences in environments where exploration has consequences.
10Exploration: ε-greedy, schedules & uncertainty

What you will learn

  • Balance gathering information with using the best-known action.
  • Explain how exploration changes the behavior, result, or engineering decision in a concrete example
  • Connect exploration with epsilon-greedy and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

An RL agent must explore because current value estimates may be wrong. ε-greedy chooses a random action with probability ε and the greedy action otherwise; schedules often reduce ε as knowledge improves.

Key concepts

explorationepsilon-greedyexploitation

Example

import random
actions=["left","right"]; epsilon=.1
choice=random.choice(actions) if random.random()<epsilon else "right"
print(choice)
Common mistake: Decaying exploration too quickly can lock the agent into a mediocre policy based on early noisy experience.
11Function approximation & neural value models

What you will learn

  • Generalize value estimates to large or continuous state spaces.
  • Explain how function approximation changes the behavior, result, or engineering decision in a concrete example
  • Connect function approximation with generalization and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

Tabular values require a separate entry for every state-action pair, which is impossible in large spaces. Function approximation predicts values or policies from features using linear models or neural networks.

Key concepts

function approximationgeneralizationneural network

Example

def q(features,weights): return sum(x*w for x,w in zip(features,weights))
print(q([1,.5],[.4,1.2]))
Common mistake: A function approximator can generalize in the wrong direction, so lower training loss does not automatically mean a better policy.
12Deep Q-Networks: replay & target networks

What you will learn

  • Explain the two major stability mechanisms in DQN.
  • Explain how DQN changes the behavior, result, or engineering decision in a concrete example
  • Connect DQN with replay buffer and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

DQN uses a neural network to approximate Q values. Consecutive environment transitions are correlated, so replay buffers randomize training batches and reuse experience.

Key concepts

DQNreplay buffertarget network

Example

buffer=[]
for t in range(5): buffer.append((t,"right",t+1))
print("replay size",len(buffer),"sample",buffer[::2])
Common mistake: Training only on the newest transition couples updates strongly to recent trajectory order and can destabilize the network.
13Policy gradients & REINFORCE

What you will learn

  • Optimize policy parameters directly using sampled returns.
  • Explain how policy gradient changes the behavior, result, or engineering decision in a concrete example
  • Connect policy gradient with REINFORCE and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

Policy-gradient methods parameterize the action distribution and adjust parameters to increase the log-probability of actions that produced high return. REINFORCE is the basic Monte Carlo policy-gradient estimator.

Key concepts

policy gradientREINFORCElog probability

Example

advantages=[1.2,-.4,.7]
log_probs=[-.2,-1.0,-.5]
loss=-sum(a*lp for a,lp in zip(advantages,log_probs))
print(round(loss,3))
Common mistake: Using raw returns without normalization or a baseline can produce very noisy gradients that require many trajectories.
14Actor-critic methods & advantage estimation

What you will learn

  • Use a learned critic to reduce policy-gradient variance.
  • Explain how actor-critic changes the behavior, result, or engineering decision in a concrete example
  • Connect actor-critic with critic and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

Actor-critic methods learn a policy actor and a value critic together. The critic estimates expected return and the actor updates using an advantage signal that compares an action’s outcome with what was expected.

Key concepts

actor-criticcriticadvantage

Example

q=5.0; v=3.8
advantage=q-v
print("advantage",advantage)
Common mistake: A poor critic can provide misleading advantages and push the policy in the wrong direction even when the policy optimizer is implemented correctly.
15PPO: clipped policy optimization

What you will learn

  • Explain how PPO limits destructive policy updates while reusing sampled data.
  • Explain how PPO changes the behavior, result, or engineering decision in a concrete example
  • Connect PPO with importance ratio and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

PPO compares the probability of sampled actions under the new and old policies using an importance ratio. Its clipped objective limits the incentive to move the ratio too far from 1, reducing the chance that one optimization phase destroys the policy.

Key concepts

PPOimportance ratioclipping

Example

ratio=1.35; eps=.2
clipped=min(max(ratio,1-eps),1+eps)
print("ratio",ratio,"clipped",clipped)
Common mistake: Treating PPO as automatically stable and ignoring KL divergence, reward curves, or entropy can allow silent policy collapse.
16Offline RL & distribution shift

What you will learn

  • Reason about learning from a fixed dataset without collecting new interaction.
  • Explain how offline RL changes the behavior, result, or engineering decision in a concrete example
  • Connect offline RL with behavior policy and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

Offline RL learns from transitions collected by a behavior policy and cannot correct mistakes by immediately gathering new data. The major challenge is distribution shift: the learned policy may choose actions that are poorly represented in the dataset, where value estimates are unreliable.

Key concepts

offline RLbehavior policydistribution shift

Example

dataset_actions={"safe":900,"risky":3}
print("coverage",dataset_actions)
Common mistake: A high predicted Q value for an action rarely seen in the offline data may be extrapolation error rather than evidence that the action is actually good.
17Imitation learning & behavior cloning

What you will learn

  • Learn a policy from demonstrations and understand compounding error.
  • Explain how imitation learning changes the behavior, result, or engineering decision in a concrete example
  • Connect imitation learning with behavior cloning and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

Behavior cloning treats expert state-action pairs as supervised learning examples. It is simple and useful when expert demonstrations are abundant, but the learned policy may visit states absent from the expert dataset; small errors can compound because the model then acts on unfamiliar inputs.

Key concepts

imitation learningbehavior cloningexpert demonstrations

Example

demos=[("clear","go"),("blocked","stop")]
policy=dict(demos)
print(policy["blocked"])
Common mistake: Evaluating only on expert-distribution states can hide the compounding-error problem that appears when the learned policy makes its own mistakes.
18Multi-agent reinforcement learning

What you will learn

  • Explain why learning becomes harder when other agents also change their policies.
  • Explain how multi-agent RL changes the behavior, result, or engineering decision in a concrete example
  • Connect multi-agent RL with non-stationarity and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

In multi-agent RL, the effective environment seen by one learner changes as other agents learn, breaking the stationarity assumption used by many single-agent methods. Tasks may be cooperative, competitive, or mixed.

Key concepts

multi-agent RLnon-stationaritycooperationcompetition

Example

rewards={"agent_A":1,"agent_B":1}
team_reward=sum(rewards.values())
print(team_reward)
Common mistake: Training against only one fixed opponent can produce a brittle policy that overfits that opponent rather than learning a robust strategy.
19RL evaluation, seeds & reproducibility

What you will learn

  • Evaluate policies across episodes, seeds, and meaningful baselines.
  • Explain how evaluation changes the behavior, result, or engineering decision in a concrete example
  • Connect evaluation with random seed and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

RL results are noisy because exploration, initialization, environment randomness, and data order all matter. A credible evaluation reports performance across multiple seeds or runs, separates training and evaluation behavior, includes simple baselines, and examines variance and failure modes—not just the best checkpoint.

Key concepts

evaluationrandom seedlearning curvebaseline

Example

scores=[82,76,88,61,84]
print("mean",sum(scores)/len(scores),"min",min(scores))
Common mistake: Reporting only the best seed or the highest single episode return can make an unstable method look reliably strong.

21Supervised fine-tuning (SFT)

What you will learn

  • Adapt a pretrained language model to desired response patterns using labeled examples.
  • Explain how SFT changes the behavior, result, or engineering decision in a concrete example
  • Connect SFT with teacher forcing and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

SFT continues next-token training on curated instruction/response data. The model is typically trained with teacher forcing while masking tokens that should not contribute to the objective, such as parts of the prompt depending on the recipe.

Key concepts

SFTteacher forcingloss masking

Example

batch={"prompt_tokens":120,"response_tokens":80,"loss_on":"response"}
print(batch)
Common mistake: Training too long on a narrow SFT dataset can overfit style, reduce general capabilities, or make the model less robust outside the training distribution.
22Preference data & reward modeling

What you will learn

  • Train or use a model that scores which of two responses better matches human preferences.
  • Explain how preference data changes the behavior, result, or engineering decision in a concrete example
  • Connect preference data with reward model and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

Preference datasets contain comparisons such as chosen versus rejected responses for the same prompt. A reward model learns a scalar preference signal from those pairs and can guide RLHF.

Key concepts

preference datareward modelpairwise ranking

Example

pair={"chosen":"concise correct answer","rejected":"confident but wrong answer"}
score={pair["chosen"]:1.2,pair["rejected"]:-.7}
print(max(score,key=score.get))
Common mistake: Treating preference labels as objective truth hides annotator disagreement and reward-model biases that can shape downstream behavior.
23RLHF with PPO

What you will learn

  • Connect a reward model, reference policy, and PPO-style policy update.
  • Explain how RLHF changes the behavior, result, or engineering decision in a concrete example
  • Connect RLHF with reward model and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

Classic RLHF treats the language model as a policy that generates responses, scores them with a reward model, and updates the policy with PPO while constraining drift from a reference model, commonly through a KL penalty.

Key concepts

RLHFreward modelPPOKL penalty

Example

reward=1.8; kl=.3; beta=.2
objective=reward-beta*kl
print("regularized reward",objective)
Common mistake: Maximizing reward-model score without controlling policy drift can produce reward hacking and outputs far from the base model distribution.
24Direct Preference Optimization (DPO)

What you will learn

  • Understand preference optimization without an explicit learned reward model plus online RL loop.
  • Explain how DPO changes the behavior, result, or engineering decision in a concrete example
  • Connect DPO with preference optimization and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

DPO converts pairwise preference learning into a supervised-style objective comparing how strongly the current policy versus a reference model prefers chosen responses over rejected ones. This removes the explicit reward-model/PPO loop from the basic pipeline and is widely used because it is simpler operationally.

Key concepts

DPOpreference optimizationreference model

Example

pairs=[("chosen A","rejected A"),("chosen B","rejected B")]
print("preference pairs",len(pairs))
Common mistake: Calling DPO “RLHF without any trade-offs” ignores sensitivity to data quality, reference model choice, and the possibility of over-optimizing a narrow preference distribution.
25GRPO, RLOO, KTO & modern post-training variants

What you will learn

  • Recognize why different post-training objectives exist and when their assumptions differ.
  • Explain how GRPO changes the behavior, result, or engineering decision in a concrete example
  • Connect GRPO with RLOO and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

Modern post-training libraries provide several objectives because tasks, feedback types, and compute constraints differ. GRPO uses relative rewards within sampled groups and is popular in reasoning-oriented online training; RLOO uses leave-one-out baselines to reduce variance; KTO can learn from desirable/undesirable examples rather than explicit pairs.

Key concepts

GRPORLOOKTOonline preference optimization

Example

rewards=[1.0,0.2,1.8,.6]
mean=sum(rewards)/len(rewards)
relative=[round(r-mean,2) for r in rewards]
print(relative)
Common mistake: Switching algorithms because one is fashionable without matching its feedback format and evaluation protocol can make training harder to interpret, not better.
26Post-training evaluation, safety & end-to-end pipeline

What you will learn

  • Design a post-training pipeline that improves target behavior without hiding regressions.
  • Explain how post-training evaluation changes the behavior, result, or engineering decision in a concrete example
  • Connect post-training evaluation with safety and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

A complete post-training system includes dataset versioning, SFT or preference stages, reproducible configs, checkpoint management, automated evaluations, human review, safety checks, and regression gates against the base or previous production model.

Key concepts

post-training evaluationsafetyregressiondata flywheel

Example

evals={"target":.84,"general":.81,"safety":.97,"latency_ms":430}
for k,v in evals.items(): print(k,v)
Common mistake: Shipping because the training loss or preference reward improved can hide regressions in unrelated capabilities or safety behavior.
