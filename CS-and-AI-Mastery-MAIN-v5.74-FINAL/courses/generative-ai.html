01What generative AI is

What you will learn

  • Define generative AI and name its major output types
  • Explain how generative vs discriminative changes the behavior, result, or engineering decision in a concrete example
  • Connect generative vs discriminative with content creation and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

Generative AI creates NEW content — text, images, audio, video — rather than just labeling or predicting a category on existing content. A spam filter is discriminative (sorts existing emails); an LLM writing an email, or a diffusion model painting an image from a text prompt, is generative (creates something new that didn't exist before).

Key concepts

generative vs discriminativecontent creationoutput modalitiescore goal

Example

# discriminative: given an email, predict spam/not-spam (a label for existing input)
# generative: given a prompt, produce a brand-new email/image/song that didn't exist before
Common mistake: Treating 'generative AI' as synonymous with 'LLMs' — image generation (GANs/diffusion), audio generation, and video generation are all equally generative AI, built on different underlying architectures.
02Generative vs discriminative models

What you will learn

  • Contrast what each model type learns and is used for
  • Explain how decision boundary changes the behavior, result, or engineering decision in a concrete example
  • Connect decision boundary with data distribution and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

A discriminative model learns a decision boundary — 'given X, what's the most likely label Y' — directly, often with less data needed for that narrow task.

Key concepts

decision boundarydata distributionP(Y|X) vs P(X)

Example

# discriminative: P(label | image) -- 'is this a cat?'
# generative: P(image) -- 'what does a realistic cat image look like, generally?'
# a generative model COULD be used to classify too, but that's not its main strength
Common mistake: Assuming a generative model is always the 'better' or 'more advanced' choice — for a pure classification task with plenty of labels, a simpler discriminative model is usually more accurate AND cheaper.
03Probability distributions & sampling

What you will learn

  • Explain what 'sampling from a distribution' means for a generative model
  • Explain how probability distribution changes the behavior, result, or engineering decision in a concrete example
  • Connect probability distribution with sampling and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

Every generative model, in some form, learns a probability distribution over its output space, then SAMPLES from it to produce something new.

Key concepts

probability distributionsamplingstochasticity

Example

# a trained model doesn't memorize ONE image of a cat --
# it learns a distribution over 'realistic cat images'
# and each generation is one random SAMPLE from that distribution
Common mistake: Treating varying outputs for the same prompt as a 'bug' — controlled randomness during sampling is a deliberate, expected part of how these models work (and is itself tunable, e.g. via temperature).
04Latent representations & major model families

What you will learn

  • Describe what a latent space is and name the major generative model families

  • Connect latent space with GANs vs VAEs vs diffusion vs transformers and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

A latent space is a compressed, lower-dimensional representation of the data's essential features — a way of describing 'what makes this image/text distinct' in far fewer numbers than the raw pixels/tokens.

Key concepts

latent spaceGANs vs VAEs vs diffusion vs transformersphotorealisticdominant approachdiffusion

Example

# same underlying idea, different mechanisms:
# GAN: generator tries to fool a discriminator
# VAE: encode to a latent distribution, decode back, sampled probabilistically
# Diffusion: learn to remove noise, step by step
# Transformer/LLM: predict the next token given context
Common mistake: Assuming all generative models work the same way underneath because they produce similar-looking outputs — the mechanisms (covered in depth in their own dedicated tracks) are genuinely.
05Training vs inference, prompting & conditioning

What you will learn

  • Distinguish training-time and inference-time, and explain conditioning
  • Explain how training vs inference changes the behavior, result, or engineering decision in a concrete example
  • Connect training vs inference with conditioning and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

Training is the (expensive, one-time-ish) process of learning the distribution from data. Inference is using the trained model to generate new outputs — cheap, per-request.

Key concepts

training vs inferenceconditioningprompt as conditioning signaltraining and inference

Example

# training: learn from millions of (image, caption) pairs -- expensive, done once (or periodically)
# inference: 'generate an image of a red bicycle' -- cheap, done per request
# the caption/prompt is the CONDITIONING signal steering what gets generated
Common mistake: Confusing fine-tuning (updating model weights, a training-time activity) with prompting (steering a fixed model at inference time, no weight changes) — they solve similar problems very.

Explanation

Unlike traditional software with fixed APIs, many generative models are controlled almost entirely through natural-language prompts -- the prompt itself becomes the 'interface' shaping behavior, tone, and output format, without writing code for each new task.

Key concepts

prompting as interfacenatural language control

Example

# same model, different prompts = different tasks:
# 'Summarize this in one sentence' vs 'List 3 risks in this text'
# no new code, no retraining -- just a different instruction
Common mistake: Assuming a generative model needs custom code for every new task, when often a well-written prompt alone can redirect its behavior.
07Evaluation, hallucination & reliability

What you will learn

  • Explain why evaluating generative models is uniquely hard, and what hallucination means
  • Explain how evaluation difficulty changes the behavior, result, or engineering decision in a concrete example
  • Connect evaluation difficulty with hallucination and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

Unlike classification, there's often no single 'correct' output to check against — many different generated images or sentences could all be 'good.' This makes evaluation genuinely hard, often requiring human judgment or proxy metrics.

Key concepts

evaluation difficultyhallucinationproxy metrics vs human judgmentevaluating generativeclassifierproxy metricshuman judgmenthuman review

Example

# no single 'correct answer' to check against, unlike a classification label
# proxy metrics exist (e.g. FID for images, perplexity for text)
# but human evaluation is still often necessary for real quality judgment
Common mistake: Assuming a confident-sounding or good-looking generated output is necessarily correct — confidence and correctness are not the same thing for generative models, ever.
08Risk: copyright, bias, privacy & misuse

What you will learn

  • Identify the major categories of risk generative AI systems raise
  • Explain how copyright provenance changes the behavior, result, or engineering decision in a concrete example
  • Connect copyright provenance with bias amplification and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

Generative models trained on large scraped datasets raise real, unresolved questions: copyright (was training on this data legal/licensed, and who owns generated output that resembles it), bias (models reproduce and can amplify biases present in training data), privacy (models can sometimes memorize and regurgitate sensitive training examples).

Key concepts

copyright provenancebias amplificationdata memorizationmisuse potentialmodel biasprovenance tracking

Example

# real, ongoing categories of concern:
# copyright -- training data provenance, output ownership
# bias -- reproducing/amplifying training-data biases
# privacy -- memorized sensitive training examples resurfacing
# misuse -- deepfakes, impersonation, disinformation at scale
Common mistake: Treating these risks as someone else's problem ('the model vendor handles that') — anyone building a product on top of generative AI inherits real responsibility for how it's used and what it outputs.
09Production use cases & choosing the right model family

What you will learn

  • Match a real use case to the right generative model family
  • Explain how model family selection changes the behavior, result, or engineering decision in a concrete example
  • Connect model family selection with use-case fit and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

Putting it together: text generation/chat -> transformers/LLMs; photorealistic image generation -> diffusion models (current state of the art); fast, real-time image synthesis or when you need an easily-manipulable latent space -> GANs or VAEs depending on the need; structured latent-space exploration or anomaly detection -> VAEs specifically.

Key concepts

model family selectionuse-case fitquality vs speed vs control trade-offsproduction choice

Example

# quick mental map:
# 'realistic', highest current quality images -> diffusion
# fast/real-time image generation, adversarial training tolerance -> GANs
# need a smooth, structured latent space to interpolate/explore -> VAEs
# any text generation/chat/reasoning task -> transformers/LLMs
Common mistake: Defaulting to 'use the newest/trendiest model family' regardless of the actual use case — GANs and VAEs still have specific, legitimate advantages diffusion models don't fully replace (e.g. GANs' inference speed, VAEs' structured latent space).
