02Text cleaning and normalization

What you will learn

  • Explain how normalization changes the behavior, result, or engineering decision in a concrete example
  • Connect normalization with casing and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

Raw text is messy: inconsistent casing, punctuation, extra whitespace, and encoding issues all add noise that makes 'Dog' and 'dog' look like different words to a naive model. Normalization — lowercasing, removing/standardizing punctuation, handling whitespace — makes text consistent before any further processing.

Key concepts

normalizationcasingwhitespace/punctuation handling

Example

text = "  The Dog's BARKING!!  "
cleaned = text.strip().lower()
cleaned = cleaned.replace("'", "")
# 'the dogs barking!!' -- more consistent, ready for tokenization
Common mistake: Over-cleaning and destroying meaningful signal — stripping ALL punctuation can lose meaningful distinctions (e.g. 'don't' vs 'dont' vs 'do not' may matter for sentiment).

04Stemming, lemmatization & bag of words

What you will learn

  • Contrast stemming vs lemmatization, and represent text as a bag of words
  • Explain how stemming changes the behavior, result, or engineering decision in a concrete example
  • Connect stemming with lemmatization and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

Stemming crudely chops word endings (running -> run, better -> better) using simple rules, fast but sometimes wrong. Lemmatization uses real vocabulary/grammar knowledge to find the correct dictionary form (better -> good), slower but more accurate.

Key concepts

stemminglemmatizationbag of wordsorder-agnostic representation

Example

# stemming (crude, fast): 'running' -> 'run', 'studies' -> 'studi' (sometimes wrong!)
# lemmatization (accurate, slower): 'running' -> 'run', 'better' -> 'good'
# bag of words: 'the cat sat' -> {'the':1, 'cat':1, 'sat':1} -- order is gone
Common mistake: Assuming bag-of-words captures meaning the way humans do — 'not good' and 'good' can end up looking very similar in a pure bag-of-words representation, losing crucial negation context.
05TF-IDF & word embeddings

What you will learn

  • Compute TF-IDF conceptually, and explain what a word embedding captures
  • Explain how TF-IDF changes the behavior, result, or engineering decision in a concrete example
  • Connect TF-IDF with term frequency and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

TF-IDF weights each word by how often it appears in a document (term frequency) DIVIDED by how common it is across all documents (inverse document frequency) — so common words like 'the' get down-weighted, while distinctive words for a specific document get boosted.

Key concepts

TF-IDFterm frequencyinverse document frequencyword embeddingssemantic similarity

Example

# TF-IDF: word appears often in THIS doc but rarely elsewhere -> high score
# 'the' -- appears everywhere -> low IDF -> low TF-IDF score, even if frequent
# 'mitochondria' -- rare overall, frequent in this doc -> high TF-IDF score
Common mistake: Using raw word counts without any IDF weighting for search/relevance ranking — extremely common words dominate the score without actually being informative.
06Practical NLP pipelines & tooling

  • Connect NLP pipeline with end-to-end and predict what changes when one assumption changes

Explanation

A real NLP pipeline typically chains: text cleaning, tokenization, feature extraction (TF-IDF or embeddings), a model, and an evaluation step -- each stage's output feeding the next. Standard libraries (like spaCy or scikit-learn's text tools) implement most of these stages reliably, so real projects rarely hand-write tokenizers or stemmers from scratch.

Key concepts

NLP pipelineend-to-endlibrary toolinglibrariesfrom scratch

Example

# typical pipeline:
# raw text -> clean/normalize -> tokenize -> TF-IDF vectorize -> classifier -> evaluate
# each stage is usually a well-tested library call, not custom code
Common mistake: Hand-writing tokenization, stemming, or vectorization from scratch for a real project when mature, well-tested libraries already handle these reliably.

09Evaluation, bias & multilingual issues

What you will learn

  • Connect F1 for NLP tasks with dialect/language bias and predict what changes when one assumption changes

Explanation

NLP evaluation needs the right metric per task (F1 for classification/NER, BLEU/ROUGE for generation/translation) — and needs to be checked across demographic and dialect groups, since language models trained mostly on one dialect or language often underperform badly on others.

Key concepts

F1 for NLP tasksdialect/language biaslow-resource languagesF1dialectlanguage bias

Example

# a documented, common failure mode:
# sentiment models trained mostly on standard/majority-dialect text
# often misclassify text written in other dialects or non-native phrasing
# -- a direct consequence of training data composition
Common mistake: Assuming strong benchmark performance in one language/dialect generalizes to others — always test explicitly on the actual populations and languages the system will serve.
