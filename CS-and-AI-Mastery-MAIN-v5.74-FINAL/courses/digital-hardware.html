01From electricity to digital information

What you will learn

  • Explain why binary states are represented by voltage ranges, not exact values
  • Explain how voltage changes the behavior, result, or engineering decision in a concrete example
  • Connect voltage with ground and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

Voltage is an electrical level measured relative to a reference point called ground. Current is the flow of charge, and resistance limits how much current flows for a given voltage -- components heat up because resistance converts some electrical energy into heat.

Key concepts

voltagegroundcurrentresistancevoltage range

Example

# conceptual, not a real measurement:
# 'digital 1' on a 5V system might mean: anything from 2.0V to 5.0V
# 'digital 0' might mean: anything from 0V to 0.8V
# voltages between 0.8V and 2.0V are ambiguous -- a well-designed circuit
# never lets a signal sit there for long
Common mistake: Assuming a digital '1' means exactly one specific voltage -- it's actually a RANGE, which is exactly why real digital systems tolerate some electrical noise without misreading a signal.
02Transistors as switches

What you will learn

  • Explain how a transistor acts as an electronically controlled switch
  • Explain how transistor changes the behavior, result, or engineering decision in a concrete example
  • Connect transistor with MOSFET and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

A transistor is a component that can be turned on or off by an electrical signal, functioning as a switch with no moving parts. A simplified MOSFET has three connections: when a control signal is applied to one, current can flow between the other two (on); without it, current can't flow (off).

Key concepts

transistorMOSFETswitchon/off state

Example

# conceptual switch behavior, not real semiconductor physics:
# control_signal = HIGH  -> switch is ON  -> current flows
# control_signal = LOW   -> switch is OFF -> current blocked
# combining many switches in specific patterns creates every digital component covered later in this course
Common mistake: Expecting to need semiconductor physics or equations to understand this -- the switch BEHAVIOR is all you need; the physics of exactly why it switches is a separate, much deeper topic this course intentionally doesn't cover.

  • Connect floating input with pull-up resistor and predict what changes when one assumption changes

Explanation

A floating input is one connected to nothing definite -- it can read as random noise instead of a clean 0 or 1, causing unpredictable behavior. A pull-up or pull-down resistor solves this by gently forcing an unconnected input toward a known state (high or low) when nothing else is driving it.

Key concepts

# fix: a pull-down resistor gently pulls it LOW when nothing else drives it,
# so it reads a clean, predictable 0 until something actively drives it HIGH
Common mistake: Assuming an unconnected digital input reads as a safe default -- without a pull-up or pull-down resistor, it can read as EITHER value unpredictably, which is a genuinely common source of.
04Fundamental digital components

Explanation

Gates are the smallest reusable hardware building blocks: NOT flips a single signal (on becomes off, off becomes on). AND only outputs on when BOTH inputs are on.

Key concepts

NOT gateAND gateOR gateXOR gateNAND gateNOR gate

Example

# thinking in terms of behavior, not formal notation:
# AND gate: output is ON only when input_1 AND input_2 are both ON

# XOR gate: output is ON only when the two inputs are DIFFERENT from each other
Common mistake: Trying to memorize gates as abstract symbolic rules -- it's far more useful (and how this course treats them) to think of each as a physical component you can toggle and observe directly in the interactive playground.
05Combinational systems

What you will learn

  • Explain what multiplexers, demultiplexers, encoders, and decoders each route or select
  • Explain how multiplexer changes the behavior, result, or engineering decision in a concrete example
  • Connect multiplexer with demultiplexer and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

A multiplexer (mux) selects ONE of several data inputs to pass through, based on a separate select signal -- like a rotary switch choosing which of several inputs reaches the output. A demultiplexer does the reverse: routes one input to one of several outputs, based on a select signal.

Key concepts

multiplexerdemultiplexerencoderdecodersignal routing

Example

# 4-to-1 multiplexer, conceptually:
# inputs = [A, B, C, D], select = 2  ->  output = C
# (the select signal literally picks which input line reaches the output)
Common mistake: Confusing an encoder with a decoder -- an encoder COMPRESSES many possible inputs into a compact code; a decoder EXPANDS a compact code back into many individual output lines. They're inverses of each other.
06Binary arithmetic hardware

What you will learn

  • Trace how a half adder and full adder combine to add multi-bit binary numbers
  • Explain how half adder changes the behavior, result, or engineering decision in a concrete example
  • Connect half adder with full adder and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

A half adder takes two single bits and produces a sum bit and a carry bit (for when both inputs are 1, needing to 'carry' into the next position -- exactly like carrying a 1 in decimal addition).

Key concepts

half adderfull addercarrymulti-bit additionoverflowALU

Example

# adding two 4-bit numbers, bit by bit, like manual long addition:
# each bit-position's full adder takes: bit_a, bit_b, carry_in
# and produces: sum_bit, carry_out (which becomes the NEXT position's carry_in)
# 4-bit example: 0111 (7) + 1001 (9) = overflow, since 16 needs 5 bits
Common mistake: Forgetting that a carry from one bit position must feed into the NEXT position's addition -- this chaining is exactly what makes multi-bit addition work, and is exactly what the 4-bit adder simulation later in this course lets you observe directly.
07Clocks and timing

What you will learn

  • Explain what a clock signal is and why faster clocks aren't automatically better
  • Explain how clock signal changes the behavior, result, or engineering decision in a concrete example
  • Connect clock signal with clock cycle and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

A clock is a signal that alternates between high and low at a steady rate, providing a shared heartbeat that synchronizes when circuits update. A rising edge (low-to-high transition) or falling edge is often the exact moment storage elements update their values.

Key concepts

clock signalclock cyclerising edgefalling edgepropagation delaycritical path

Example

# why clock speed has limits, conceptually:
# if the slowest signal path takes 3 nanoseconds to settle,
# the clock period must be AT LEAST slightly more than 3ns --
# otherwise the next clock edge arrives before the signal has finished settling,
# and the wrong (not-yet-settled) value gets captured
Common mistake: Assuming a faster clock is always strictly better -- if the critical path can't keep up, a faster clock causes real, hard-to-diagnose timing failures rather than faster correct operation.
08Storing one bit and many bits

What you will learn

  • Explain why combinational circuits alone cannot remember, and how flip-flops and registers do
  • Explain how latch changes the behavior, result, or engineering decision in a concrete example
  • Connect latch with flip-flop and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

A purely combinational circuit's output depends ONLY on its current inputs -- it has no memory of the past. A latch or flip-flop is different: it can hold ('store') a value, changing only at specific moments (like a clock edge), and holding steady otherwise.

Key concepts

latchflip-flopregisterenable signalreset signalshift register

Example

# a 1-bit storage element's behavior, conceptually:
# on a clock edge: if reset is active, value becomes 0
#                  else if enable is active, value becomes the current input
#                  else, value stays exactly as it was (this is the 'memory' part)
Common mistake: Assuming any circuit can just 'remember' a value automatically -- memory requires a DELIBERATE storage element (a flip-flop or register); wires and gates alone have no memory at all.

10Memory systems

What you will learn

  • Distinguish registers, cache, RAM, and storage, and explain how a CPU addresses memory
  • Explain how memory hierarchy changes the behavior, result, or engineering decision in a concrete example
  • Connect memory hierarchy with address lines and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

Memory exists in a hierarchy by speed, size, and cost: registers (fastest, tiniest, right on the CPU), cache (small and fast), RAM (larger, slower, holds a running program's data), and storage/disk (largest, slowest, persists after power off).

Key concepts

memory hierarchyaddress linesdata linesread/write controlSRAMDRAMROMflash memory

Example

# reading from memory, conceptually:
# 1. CPU puts the desired address on the address lines
# 2. CPU sets the 'read' control signal active
# 3. memory responds by placing the stored data at that address
#    onto the data lines, for the CPU to read
Common mistake: Confusing 'more memory' with 'faster memory' -- the hierarchy exists specifically because faster memory is far more expensive per bit, so systems use a small amount of very fast memory alongside a much larger amount of slower memory.
11Datapaths and ALUs

What you will learn

  • Trace how registers, a bus, a multiplexer, and an ALU combine into a working datapath
  • Explain how datapath changes the behavior, result, or engineering decision in a concrete example
  • Connect datapath with bus and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

A datapath is the arrangement of registers, buses (shared wires carrying data between components), multiplexers (selecting which value flows where), and an ALU (performing the actual computation) that together move and transform data under the direction of control signals.

Key concepts

datapathbuscontrol signalsALU operation selection

Example

# tracing one operation through a datapath, conceptually:
# 1. control signals select Register A and Register B as ALU inputs (via multiplexers)
# 2. control signal selects 'ADD' as the ALU operation
# 3. ALU computes A + B
# 4. control signal selects Register C as the destination
# 5. on the next clock edge, Register C stores the ALU's result
Common mistake: Assuming each operation needs its OWN dedicated circuit -- the whole point of a datapath is REUSING the same registers, bus, and ALU for many different operations, just with different.
12Building a tiny processor

What you will learn

  • Trace the fetch-decode-execute cycle through a small, concrete instruction set
  • Explain how program counter changes the behavior, result, or engineering decision in a concrete example
  • Connect program counter with instruction register and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

A tiny processor combines everything from this course: a program counter (tracks which instruction is next), an instruction register (holds the current instruction being processed), a small set of general registers, and an ALU -- all connected by a datapath.

Key concepts

program counterinstruction registerfetchdecodeexecuteinstruction set

Example

# fetch-decode-execute, one instruction at a time:
# FETCH:   read instruction at program_counter, e.g. "ADD R2, R0, R1"
# DECODE:  operation=ADD, destination=R2, sources=R0 and R1
# EXECUTE: R2 = R0 + R1 (using the ALU and datapath from the previous lessons)
# advance program_counter, repeat
Common mistake: Confusing this course's focus (how the hardware BLOCKS are built and connected) with the Computer Architecture course's focus (how a COMPLETED processor and operating system behave) -- they're deliberately complementary, not duplicates.
13Hardware interfaces

What you will learn

  • Distinguish GPIO, UART, SPI, and I²C at the signal level, and when each is used
  • Explain how GPIO changes the behavior, result, or engineering decision in a concrete example
  • Connect GPIO with UART and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

GPIO (General Purpose Input/Output) pins can be individually configured as simple digital inputs or outputs -- the most basic way a processor reads a switch or drives an LED. UART is a simple serial protocol sending one bit at a time over a single wire pair, commonly used for basic device-to-device communication.

Key concepts

GPIOUARTSPII²Cchip-selectserial vs parallel communication

Example

# choosing an interface, conceptually:
# one on/off LED or button -> GPIO is simplest, no protocol needed
# two devices, simple messages, few wires -> UART
# one fast device, dedicated wires available -> SPI
# several devices sharing very few wires, each with an address -> I2C
Common mistake: Assuming one interface is universally 'best' -- each is a genuine trade-off between speed, wire count, and how many devices need to share the connection; the right choice depends on the actual scenario.
14Hardware debugging

What you will learn

  • Explain how floating input changes the behavior, result, or engineering decision in a concrete example
  • Connect floating input with reset polarity and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

Real hardware faults tend to fall into recognizable patterns: a floating input reads unpredictably because nothing is driving it firmly. Incorrect reset polarity means a circuit designed for active-low reset gets an active-high signal (or vice versa), so it never resets when expected -- or resets constantly.

Key concepts

floating inputreset polaritymissing enableclock not reaching a componentchip-select faultoff-by-one countertiming diagram

Example

# recognizing symptoms, conceptually:
# 'this register never seems to update' -> check: is enable actually reaching it? is the clock reaching it?
# 'this circuit resets at the wrong times' -> check: active-high vs active-low reset polarity mismatch
# 'random/flickering behavior on this input' -> check: is it floating (missing a pull-up/pull-down)?
Common mistake: Assuming a hardware bug must be exotic -- the vast majority of real digital hardware faults are exactly these few recognizable patterns, which is why this lesson lists them explicitly rather.

Exercises

Identify a floating input

A digital input pin is connected to nothing else and randomly flickers between reading 0 and 1. What is this problem called, and what's the standard fix?

Hint

a floating input; fixed with a pull-up or pull-down resistor to give it a defined default state

Choose pull-up or pull-down

You want an unconnected button input to default to reading 0 (LOW) until the button is pressed. Would you use a pull-up or pull-down resistor?

Hint

a pull-down resistor, since it forces the default state toward LOW (0)

Predict an active-low reset

A component's reset input is active-low, but the circuit driving it holds the line HIGH by default and only pulls it LOW briefly during a fault. Under normal operation, is the component held in reset or allowed to run?

Hint

allowed to run -- active-low reset only triggers when the line goes LOW, and it's HIGH under normal operation

Select the correct digital component

You need one input out of eight to be selected and routed to a single output, based on a 3-bit select code. Which component do you need?

Hint

a multiplexer (specifically an 8-to-1 mux, since 3 select bits can address 8 inputs)

Route a multiplexer

Given a 4-to-1 multiplexer with inputs [A=10, B=20, C=30, D=40] and select=1, what value reaches the output?

Hint

20 (select=1 picks the second input, B, using 0-indexing)

Trace a multi-bit adder

Add the 4-bit binary values 0110 (6) and 0011 (3) using a chain of full adders. What is the 4-bit result and is there a carry-out?

Hint

1001 (9), no carry-out, since 6+3=9 fits within 4 bits (max 15)

Detect overflow

Adding two 4-bit values 1111 (15) and 0001 (1) produces what result, and does it overflow a 4-bit register?

Hint

the true sum is 16, which needs 5 bits -- so yes, it overflows a 4-bit register (the stored result would incorrectly show 0000 with a carry-out of 1)

Trace register contents across clock edges

A register starts at 0. On clock edge 1: enable=1, input=5. On clock edge 2: enable=0, input=9. On clock edge 3: enable=1, input=7. What is the register's value after each edge?

Hint

after edge 1: 5 (enabled, takes input). after edge 2: 5 (not enabled, unchanged). after edge 3: 7 (enabled, takes new input)

Diagnose why a counter does not advance

A binary counter is supposed to increment every clock cycle but stays frozen at its current value. List two plausible hardware causes.

Hint

the clock signal isn't actually reaching the counter, or the enable signal is stuck low/inactive

Read a timing diagram

A timing diagram shows a clock signal rising at time T, and a data signal changing shortly AFTER T on every cycle. Is the data signal likely being captured correctly on that clock edge?

Hint

likely NOT reliably -- data should be stable and settled BEFORE the clock edge (respecting setup time), not changing shortly after it

Repair an incorrect enable connection

A register's enable input is accidentally wired directly to ground (permanently 0/inactive) instead of to the intended control signal. What visible symptom would this cause?

Hint

the register would never update, appearing permanently frozen at whatever value it happened to hold on startup

Diagnose reset polarity

A flip-flop expects an active-high reset, but the circuit was built assuming active-low reset logic. What would you observe?

Hint

the flip-flop would reset constantly (since the line is normally LOW, which the flip-flop wrongly reads as its OWN active-high trigger) or never reset at all, depending on which way the mismatch runs

Trace data through a datapath

A datapath's control signals select Register A and Register B as ALU inputs, ADD as the operation, and Register C as the destination. If A=4 and B=6, what value does Register C hold after the next clock edge?

Hint

10 (4+6), stored into Register C on the clock edge

Identify the next processor state

A tiny processor's program counter is at instruction 2 of a 4-instruction program (LOAD, LOAD, ADD, HALT). After executing the ADD instruction, what happens to the program counter and what executes next?

Hint

the program counter advances to instruction 3, and the HALT instruction executes next, stopping the processor

Choose between UART, SPI, and I²C

You need to connect six sensors to a microcontroller using as few wires as possible, and speed isn't critical. Which interface fits best, and why?

Hint

I²C -- it supports many addressed devices on just two shared wires, trading speed for minimal wiring, which matches this scenario's priorities

Diagnose a chip-select problem

Two SPI devices share the same data lines but their chip-select signals are accidentally both wired active at the same time. What symptom would this likely cause?

Hint

both devices try to respond simultaneously on the shared data line, causing conflicting/garbled data (bus contention) rather than a clean response from either device

Find a signal-arrival timing problem

A signal needs to travel through 3 gates before reaching a register, and the clock period is shorter than the time all 3 gates need to settle. What happens on each clock edge?

Hint

the register may capture an incorrect, not-yet-settled value, since the signal hasn't finished propagating through all 3 gates before the next clock edge arrives

Debug a small controller

A traffic-light controller's finite-state machine is stuck permanently in the 'red' state and never transitions to 'green,' even though the timer input is confirmed to be firing correctly. What's a plausible cause?

Hint

the transition logic/wiring from the 'red' state to the 'green' state on a timer-expired input may be missing, broken, or pointing back to 'red' instead of forward to 'green'
