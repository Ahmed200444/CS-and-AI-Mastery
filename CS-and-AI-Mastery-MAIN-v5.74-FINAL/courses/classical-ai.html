01Intelligent agents & problem formulation

What you will learn

  • Formulate a real problem as states, actions, goals, and costs.
  • Explain how agent changes the behavior, result, or engineering decision in a concrete example
  • Connect agent with state and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

Classical AI begins by choosing a representation that makes reasoning possible. An agent observes an environment and chooses actions; a search problem specifies an initial state, possible actions, transition model, goal test, and path cost.

Key concepts

agentstateactiongoalenvironment

Example

problem={"start":"A","goal":"G","actions":{"A":["B","C"],"B":["G"],"C":[]}}
print(problem["start"],"->",problem["goal"])
Common mistake: Choosing a state representation that omits information needed for future decisions can make the correct solution impossible to express.
02State spaces, graphs & search trees

What you will learn

  • Distinguish the underlying state graph from the search tree generated by an algorithm.
  • Explain how state space changes the behavior, result, or engineering decision in a concrete example
  • Connect state space with search tree and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

A state space is the set of possible configurations and transitions. A search tree is the algorithm’s unfolding of that space from the start state, so the same world state may appear many times through different paths.

Key concepts

state spacesearch treerepeated state

Example

graph={"A":["B","C"],"B":["A","D"],"C":["D"],"D":[]}
visited=set()
print("states:",len(graph))
Common mistake: Treating every search-tree node as a new world state can cause exponential repeated work in cyclic or converging graphs.
03Breadth-first & depth-first search

What you will learn

  • Choose BFS or DFS based on solution depth, memory, and completeness.
  • Explain how BFS changes the behavior, result, or engineering decision in a concrete example
  • Connect BFS with DFS and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

Breadth-first search expands the shallowest frontier first and is complete on finite branching graphs; with equal step costs it finds a shortest path in number of edges. Depth-first search follows one branch deeply using little frontier memory but can waste time down an unhelpful path and needs cycle handling.

Key concepts

BFSDFSfrontier

Example

from collections import deque
g={"A":["B","C"],"B":["D"],"C":["E"],"D":[],"E":[]}
q=deque(["A"]); seen={"A"}
while q:
    n=q.popleft(); print(n,end=" ")
    for x in g[n]:
        if x not in seen: seen.add(x); q.append(x)
Common mistake: Using DFS when the search space can contain an infinite branch can prevent the algorithm from ever reaching a nearby solution elsewhere.
04Uniform-cost search & path cost

What you will learn

  • Find the least-cost path when actions have different costs.
  • Explain how uniform-cost search changes the behavior, result, or engineering decision in a concrete example
  • Connect uniform-cost search with priority queue and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

Uniform-cost search expands the frontier node with the lowest accumulated path cost g(n). With non-negative step costs, the first time a goal is removed from the priority queue its cost is optimal.

Key concepts

uniform-cost searchpriority queuepath cost

Example

import heapq
frontier=[(0,"A")]
heapq.heappush(frontier,(5,"C")); heapq.heappush(frontier,(2,"B"))
print(heapq.heappop(frontier))
Common mistake: Marking a node permanently visited when it is first generated rather than when its best cost is established can discard a cheaper path found later.
05Heuristics & greedy best-first search

What you will learn

  • Design a heuristic and understand what information it adds to search.
  • Explain how heuristic changes the behavior, result, or engineering decision in a concrete example
  • Connect heuristic with greedy best-first and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

A heuristic h(n) estimates remaining cost from a state to a goal. Greedy best-first search expands the state with the smallest heuristic estimate, often reaching a goal quickly but without considering the cost already paid.

Key concepts

heuristicgreedy best-firstinformed search

Example

heuristic={"A":6,"B":2,"C":4,"G":0}
print(min(["B","C"], key=heuristic.get))
Common mistake: A heuristic that looks intuitive but systematically overvalues the wrong feature can make informed search worse than a simpler baseline.
06A* search, admissibility & consistency

What you will learn

  • Explain why A* balances known path cost with estimated remaining cost.
  • Explain how A* changes the behavior, result, or engineering decision in a concrete example
  • Connect A* with admissible heuristic and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

A* orders states by f(n)=g(n)+h(n), combining the cost already paid with an estimate of the cost remaining. An admissible heuristic never overestimates the true remaining cost; consistency adds a triangle-inequality-style condition across edges and makes graph-search behavior cleaner.

Key concepts

A*admissible heuristicconsistent heuristicf=g+h

Example

g={"A":0,"B":3,"C":1}; h={"A":4,"B":1,"C":4}
for n in g: print(n,"f=",g[n]+h[n])
Common mistake: Using a heuristic because it “usually seems close” without checking its admissibility can silently remove the optimality guarantee.
07Local search: hill climbing & simulated annealing

What you will learn

  • Use local search when the path is irrelevant and only a good final state matters.
  • Explain how hill climbing changes the behavior, result, or engineering decision in a concrete example
  • Connect hill climbing with local optimum and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

Local search keeps one or a small number of candidate states and improves an objective rather than constructing a path from start to goal. Hill climbing moves to a better neighbor but can become trapped on local optima, ridges, or plateaus.

Key concepts

hill climbinglocal optimumsimulated annealing

Example

scores=[3,5,7,6,9]
best=scores[0]
for s in scores[1:]:
    if s>best: best=s
print("best observed",best)
Common mistake: Assuming hill climbing found the global optimum because no immediate neighbor is better confuses local optimality with global optimality.
08Constraint satisfaction & backtracking

What you will learn

  • Model a problem as variables, domains, constraints, and a systematic search.
  • Explain how CSP changes the behavior, result, or engineering decision in a concrete example
  • Connect CSP with variable and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

Constraint Satisfaction Problems separate representation from search: variables must receive values from domains while satisfying constraints. Backtracking assigns one variable at a time and reverses choices when a constraint fails.

Key concepts

CSPvariabledomainconstraintbacktracking

Example

colors=["R","G","B"]
solutions=[(a,b) for a in colors for b in colors if a!=b]
print(solutions)
Common mistake: Generating complete assignments before checking constraints throws away the main advantage of backtracking: pruning impossible partial solutions early.
09Constraint propagation, MRV & arc consistency

What you will learn

  • Reduce CSP search by propagating constraints before making more guesses.
  • Explain how MRV changes the behavior, result, or engineering decision in a concrete example
  • Connect MRV with forward checking and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

Constraint propagation removes domain values that cannot participate in a valid solution. Forward checking prunes neighbors after an assignment; arc consistency repeatedly ensures each value of one variable has compatible support in a connected variable.

Key concepts

MRVforward checkingarc consistencyAC-3

Example

domains={"A":{1,2},"B":{1,2}}
domains["A"]={1}
domains["B"]-=domains["A"]
print(domains)
Common mistake: Propagation must preserve only logically impossible values; over-pruning can delete valid solutions and make the solver appear fast but incorrect.
10Adversarial search & minimax

What you will learn

  • Choose an action assuming an opponent also acts rationally.
  • Explain how minimax changes the behavior, result, or engineering decision in a concrete example
  • Connect minimax with MAX and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

Adversarial search models environments where another agent actively tries to reduce your outcome. Minimax alternates MAX nodes, which choose the highest utility, and MIN nodes, which choose the lowest utility from MAX’s perspective.

Key concepts

minimaxMAXMINgame tree

Example

children=[3,-2,5]
print("MAX chooses",max(children),"MIN chooses",min(children))
Common mistake: Evaluating only your own best next move ignores the opponent’s response and produces plans that fail immediately against rational play.
11Alpha-beta pruning & evaluation functions

What you will learn

  • Prune game-tree branches that cannot affect the minimax decision.
  • Explain how alpha-beta pruning changes the behavior, result, or engineering decision in a concrete example
  • Connect alpha-beta pruning with evaluation function and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

Alpha-beta pruning computes the same minimax choice while skipping branches proven irrelevant to the final result. Alpha tracks MAX’s best guaranteed value so far; beta tracks MIN’s.

Key concepts

alpha-beta pruningevaluation functionmove ordering

Example

def evaluate(position):
    return position["my_score"]-position["opp_score"]
print(evaluate({"my_score":7,"opp_score":4}))
Common mistake: A fast evaluation function with poor correlation to winning can make deeper search confidently choose bad moves.
12Propositional logic & knowledge bases

What you will learn

  • Represent facts and rules with precise truth conditions.
  • Explain how proposition changes the behavior, result, or engineering decision in a concrete example
  • Connect proposition with logical connective and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

Propositional logic represents statements that are true or false and combines them with NOT, AND, OR, implication, and equivalence. A knowledge base is a set of sentences; entailment asks whether every model that satisfies the knowledge base also satisfies a query.

Key concepts

propositionlogical connectiveknowledge basemodel

Example

rain=True; umbrella=True
print("protected from rain:", (not rain) or umbrella)
Common mistake: Treating implication P→Q as if it also means Q→P is the classic converse error and produces invalid conclusions.
13Logical inference, entailment & resolution

What you will learn

  • Derive conclusions using sound inference rather than intuition.
  • Explain how entailment changes the behavior, result, or engineering decision in a concrete example
  • Connect entailment with resolution and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

Inference algorithms transform or inspect a knowledge base to prove consequences. Resolution works conveniently with clauses in conjunctive normal form and proves a query by showing that adding its negation leads to contradiction.

Key concepts

entailmentresolutionCNFproof

Example

facts={"cloudy", "cloudy->rain"}
if "cloudy" in facts and "cloudy->rain" in facts: print("derive: rain")
Common mistake: Using a plausible real-world belief that was never encoded in the knowledge base is not logical inference from the represented facts.
14First-order logic & unification

What you will learn

  • Represent objects, relations, variables, and quantified rules.
  • Explain how first-order logic changes the behavior, result, or engineering decision in a concrete example
  • Connect first-order logic with predicate and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

First-order logic extends propositional logic with objects, predicates, functions, variables, and quantifiers. Instead of a separate proposition for every person, a rule can state that all humans satisfy some property.

Key concepts

first-order logicpredicatequantifierunification

Example

rule=("parent", "X", "Y")
fact=("parent", "Ada", "Byron")
substitution={rule[1]:fact[1],rule[2]:fact[2]}
print(substitution)
Common mistake: Confusing existential “there exists” with universal “for all” changes the meaning of a rule completely.
15Knowledge representation: rules, frames & ontologies

What you will learn

  • Choose a representation that exposes the relationships an inference task needs.
  • Explain how knowledge representation changes the behavior, result, or engineering decision in a concrete example
  • Connect knowledge representation with ontology and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

Knowledge representation is the engineering decision about how concepts, categories, attributes, relations, defaults, and rules are encoded. Rule systems are good for explicit implications, graph/ontology representations are good for typed entities and relationships, and structured frames can group properties around concepts.

Key concepts

knowledge representationontologyrulerelation

Example

knowledge={"Ada":{"type":"Person","skills":{"math","programming"}}}
print("programming" in knowledge["Ada"]["skills"])
Common mistake: A representation that stores facts but cannot express the relationships needed by the reasoning task forces complex, brittle application code later.
16Reasoning under uncertainty & Bayes networks

What you will learn

  • Represent uncertain dependencies and update beliefs from evidence.
  • Explain how Bayes network changes the behavior, result, or engineering decision in a concrete example
  • Connect Bayes network with conditional probability and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

Real environments rarely provide complete certainty. Bayesian networks represent random variables as a directed acyclic graph whose edges capture conditional dependencies; local conditional probability tables define the joint distribution compactly when independences hold.

Key concepts

Bayes networkconditional probabilityindependence

Example

prior=0.01; sensitivity=0.9; false_positive=0.05
p_pos=prior*sensitivity + (1-prior)*false_positive
posterior=prior*sensitivity/p_pos
print(round(posterior,3))
Common mistake: Interpreting P(test positive | disease) as P(disease | test positive) ignores the base rate and is a common probabilistic reasoning error.
17Planning with actions, preconditions & effects

What you will learn

  • Represent a goal-directed plan as actions that transform symbolic state.
  • Explain how planning changes the behavior, result, or engineering decision in a concrete example
  • Connect planning with precondition and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

Classical planning separates action definitions from the specific problem instance. An action has preconditions that must be true before it can execute and effects that change the state.

Key concepts

planningpreconditioneffectSTRIPS

Example

state={"at_A":True,"door_open":False}
if state["at_A"]:
    state["door_open"]=True
print(state)
Common mistake: Allowing an action to execute without checking its preconditions creates impossible plans that look valid only because state transitions were under-specified.
18Plan-space, hierarchical & partial-order planning

What you will learn

  • Reason about plans without forcing every action into a fixed total order too early.
  • Explain how partial-order planning changes the behavior, result, or engineering decision in a concrete example
  • Connect partial-order planning with hierarchical planning and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

Some planning problems are easier when the system commits only to ordering constraints that are necessary. Partial-order planning can leave independent actions unordered, while hierarchical planning decomposes abstract tasks into smaller methods and actions.

Key concepts

partial-order planninghierarchical planningsubgoal

Example

tasks={"deploy":["build","test","release"],"notify":["compose","send"]}
print("independent high-level tasks:",list(tasks))
Common mistake: Imposing an arbitrary total order on independent tasks can remove concurrency and expand the search space without improving correctness.
19Markov Decision Processes as a bridge to RL

What you will learn

  • Model sequential decisions where actions have uncertain outcomes.
  • Explain how MDP changes the behavior, result, or engineering decision in a concrete example
  • Connect MDP with transition probability and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

A Markov Decision Process specifies states, actions, transition probabilities, rewards, and a discount factor. Unlike deterministic planning, an action may lead to several next states with different probabilities.

Key concepts

MDPtransition probabilityrewardpolicy

Example

transitions={"safe":{"reward":1,"next":"safe"},"risky":{"reward":3,"next":"unknown"}}
print(transitions)
Common mistake: Choosing the action with the largest immediate reward can be worse over time when it leads to poor future states.
20Choosing the right AI formulation & evaluating search

What you will learn

  • Select search, CSP, logic, planning, probability, or learning based on problem structure.
  • Explain how problem formulation changes the behavior, result, or engineering decision in a concrete example
  • Connect problem formulation with baseline and predict what changes when one assumption changes
  • Verify the idea with a normal case and an important edge, failure, or scale case

Explanation

Near-mastery is the ability to recognize the structure before reaching for an algorithm. If you need a path, use search; if you need a consistent assignment, consider CSP; if you need provable symbolic consequences, use logic; if actions achieve symbolic goals, use planning; if uncertainty matters, use probabilistic models or MDPs.

Key concepts

problem formulationbaselineevaluationalgorithm selection

Example

choices={"route":"A*","schedule":"CSP","proof":"logic","stochastic_control":"MDP"}
for problem,method in choices.items(): print(problem,"->",method)
Common mistake: Picking an algorithm because it is advanced or fashionable instead of because its assumptions match the problem often creates unnecessary complexity.
