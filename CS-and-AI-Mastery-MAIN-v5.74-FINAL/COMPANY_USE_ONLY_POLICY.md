# CS & AI Mastery v5.47 — Company-Use-Only Expansion Policy

## Rule

New curriculum material is added only when it maps to a concrete software-engineering, AI, ML, data, infrastructure, security, embedded, or other engineering task that can occur in real company work. Material is not added merely because it is academically interesting.

## What qualifies

A new lesson, example, exercise, or project should help with at least one real engineering action: build, debug, test, evaluate, design, deploy, operate, secure, optimize, analyze data, communicate an engineering decision, or diagnose a production failure. Role-specific material can stay in a specialization course, but it should not be presented as mandatory core knowledge for every engineer.

## ML math decision

The platform does **not** add a separate theory-heavy math course. The useful math is embedded where engineers actually need it:

- **Linear algebra:** vectors, feature vectors, weighted sums, dot products, matrix multiplication, tensor shapes.
- **Statistics/probability:** means/rates, standard deviation/variance, sampling, class proportions, distributions, experiment/model-metric interpretation.
- **Calculus:** gradient, partial-derivative, and chain-rule intuition for optimization/backpropagation. No symbolic-calculus drill track.

## Explicit exclusions from future expansion

Do not add proof-only derivations, long symbolic-calculus exercises, abstract matrix proofs, or historical/theoretical material unless it directly changes an engineer's ability to implement, debug, evaluate, optimize, secure, or operate a real system.
